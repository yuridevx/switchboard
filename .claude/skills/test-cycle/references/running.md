# Шаг «прогон»

Прогон узнаёт по факту, ведёт ли себя система так, как написано в плане. Он только наблюдает: план, код, тесты и стенд не правит — иначе его вердикту нельзя верить.

Вход — папка плана или путь к страницам флоу того же вида; можно подмножество сценариев. Плана нет — отказ с причиной.

## Что гоняется

1. `npm run gate` и typecheck.
2. Тесты частей охвата — целиком; сценарий получает исход теста из своего поля «Тест».
3. Сценарии «вживую» — на выложенном тестовом флоте.

## Свойства прогона

- Сценарий «вживую» начинается с чистого состояния: следы прошлых сценариев на его исход не влияют.
- Шаги идут через публичные входы системы; исход читается по наблюдаемому — тому, что названо в «Ожидаем».
- Исход сценария — один из трёх:
  - **PASS** — тест зелёный или каждое «Ожидаем» подтверждено вживую;
  - **FAIL** — тест красный, или хоть одно «Ожидаем» опровергнуто или не наблюдается;
  - **SKIPPED** — только когда план сам держит сценарий в нерешённом или границу нельзя поднять; причина записана.
- «Не удалось понять» не бывает: наблюдать не вышло — это FAIL, в доказательстве — почему.
- Система не поднялась — прогон останавливается, FAIL с причиной.

## fails.md

Только дописывается, записи не правятся. Тот же провал в новом прогоне — новая запись: повтор тоже факт. Провал — FAIL сценария, красный тест вне плана или упавший гейт. Находка ли это, решает шаг «находки».

```markdown
## FAIL 007 — <flow-id> · <сценарий> | гейт | тест вне плана
- Прогон: <номер> · <время UTC> · что: гейт | тест | вживую
- Ожидаем (из плана, дословно): …
- Наблюдали: …
- Воспроизвести (от чистого состояния): <команды>
- Доказательство: вывод, коды выхода, строки журнала — дословно
- Код: <файл>:<строка> — вход и ссылки страницы
```

## run.md

- Строка на каждый прогон: номер, время, PASS / FAIL / SKIPPED, записи FAIL.
- Карта последнего прогона: флоу × сценарий → исход, номер записи FAIL.
- Пропущенное — с причинами.

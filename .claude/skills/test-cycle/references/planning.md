# Шаг «план»

План описывает, как система должна себя вести, флоу за флоу: по нему пишутся тесты и прогоняется система. Он только описывает — код и тесты не правит. Решения развилок — одной строкой в `plan.md`.

Охват — модуль, Worker-модуль, приложение, всё репо или названные флоу: как назвал пользователь или deliver.

## Понятия

| понятие | что это |
|---|---|
| вход | место в коде, где флоу начинается по внешнему стимулу: кадр, запрос, HTTP или WebSocket Worker-модуля, событие SDK, сигнал ОС, таймер, действие в веб-приложении, команда CLI |
| флоу | путь от одного входа до наблюдаемого исхода; у флоу одна часть-владелец |
| сквозной флоу | флоу через две и больше частей по их контрактам; инициатор один |
| наблюдаемый исход | то, что видно снаружи части: ответ `reply`, кадр, поле roster, запись в хранилище, строка журнала с причиной, процесс поднят или остановлен, сообщение во вводе сессии, экран, пуш — или документированное отсутствие этого |
| ветка | развилка в коде, которая даёт другой наблюдаемый исход |
| `flow-id` | стабильное kebab-имя из стимула и символа входа: `request-session-prompt`, `frame-message`, `timer-points-retention`, `cross-fleet-send`; тот же код — то же имя |

## Какие сценарии

- **HAPPY** — основной путь флоу.
- **NEGATIVE** — только ожидаемые ветки устава: закрытый список восстановления, отказ «система ловит» (остановила, отказала, записала причину) и штатная остановка, если она у части есть. Вся валидация входа — один сценарий «вход отклонён»: крайние случаи устав не закрывает и не тестирует.

Сценарий начинается на входе и кончается наблюдаемым исходом; внутреннее состояние части не проверяется — иначе тест закрепит устройство, а не поведение.

## Страница флоу

```markdown
# <flow-id>

## Флоу
Стимул: <кадр / запрос / таймер / …>
Вход: <файл>:<строка>
Суть: <одна фраза>

## Сценарии

### <имя по сути> · HAPPY
- Условия: хранилище — …; вход — …; настройка — …; соседи — …
- Шаги: 1. … 2. …
- Ожидаем: <наблюдаемый исход> — источник: слово пользователя «…» | факт: … | чьё: код
- Подделки: нет | <граница> — <почему>
- Код: <файл>:<строка>, …
- Тест: <файл> · <номер> · <имя> | вживую — ставит шаг «тесты»

### <имя по сути> · NEGATIVE
- Ветка: <файл>:<строка> — <условие>
- (те же поля)
```

В сквозном флоу шаг — `часть → часть: кадр или запрос`, без внутренних шагов частей.

## Правила страницы

1. Источник истины — код и слово пользователя (устав, принятые дизайны). Существующие тесты, README и прочие документы — не доказательство: «Ожидаем» на них не ссылается.
2. У каждого «Ожидаем» есть источник.
3. Каждая ссылка `файл:строка` указывает на тот символ, о котором сказано.
4. Каждый вход охвата — ровно в одном флоу или в исключении с причиной.
5. Каждая ожидаемая ветка — сценарий NEGATIVE со строкой «Ветка».
6. Подделка — только на границе части (SDK, Relay, Keeper, часы, внешние сервисы), с названной границей и причиной. Соседние модули внутри флоу — настоящие.
7. Условия описаны словами, без ссылок на фикстуры.
8. Имена сценариев уникальны на странице и говорят суть: «повтор после смерти процесса», а не «error case».
9. Пустых разделов нет.

## Слепое расширение

Каждую страницу после автора расширяет новый агент (Agent, `subagent_type: general-purpose`), который автора не видел; запускает его главная сессия. Слово пользователя 1 нояб.: его задача — «посмотреть вслепую на план и расширить его по принципам устава: продумать все счастливые пути, валидные краевые случаи и валидные по ценностям сценарии ошибок».

- Дописывает, чего на странице нет: счастливые пути, ожидаемые ветки устава, сценарии ошибок «система ловит». Валидно то, что устав держит в ожидаемых ветках; прочие крайние случаи не дописываются.
- Новые сценарии — по правилам страницы, с источником «Ожидаем» и ссылками на код.
- Написанное автором правит только по существу: нет обязательного поля, утверждение противоречит коду, вход или ветка без сценария, неверная ссылка, нарушено правило. Формулировки, порядок и оформление не трогает.
- Расширение одно на страницу; что оно не закрыло — в «нерешённое».

## plan.md

- **Охват:** части, входы, флоу, сквозные флоу, сценарии HAPPY и NEGATIVE — числами; из них дописанные слепым расширением.
- **Карта покрытия:** вход → флоу или исключение; ветка → сценарий. Сирот нет.
- **Нерешённое:** пункт, страница, причина и закрывающий вариант — им пункт и закрыт, если пользователь не скажет иначе.

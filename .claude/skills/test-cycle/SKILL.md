# Цикл тестирования

Охват X — часть или названные флоу — описан планом, каждое свойство плана закреплено одним тестом, система проходит план на тестовом флоте, открытых находок 0.

```
план → тесты → выкладка → прогон → находки ─┐
                  ▲                         │
                  └─────────────────────────┘  пока находки есть
```

| шаг | кто | как | готово, когда |
|---|---|---|---|
| план | форк; слепое расширение — агенты с нуля | `references/planning.md` | страницы расширены, сирот в карте покрытия нет, у каждого «Ожидаем» источник |
| тесты | форк | `references/covering.md` | у каждого сценария заполнен «Тест», дубликатов 0 |
| выкладка | главная сессия | шаг «Выпуск» скила deliver; только если в плане есть сценарии «вживую» | тронутое на тестовом флоте |
| прогон | форк | `references/running.md` | у каждого сценария исход, у каждого провала запись |
| находки | форк | `references/findings.md` | открытых находок 0; у каждой причина, фикс, регрессия |

Вызов с названием шага делает только этот шаг на уже лежащем плане.

## Кто что делает

Главная сессия ведёт цикл и выкладывает: живой флот — один исполнитель.

Форк — один на весь цикл (Agent, `subagent_type: fork`): он уже знает код, дизайн и решения пользователя, и следующий шаг ему не надо объяснять заново. Следующие шаги и круги — сообщением ему же (SendMessage). Форк читает файл своего шага; агентов сам не запускает.

Агенты с нуля — только на слепое расширение плана: там ценен взгляд, который не видел автора. Их запускает главная сессия.

## Файлы

`<scratchpad>/test-plan/<slug>/` (`slug` — kebab-имя охвата):

| файл | пишет шаг | что это |
|---|---|---|
| `flows/<flow-id>.md` | план; поле «Тест» — тесты | страница флоу со сценариями |
| `plan.md` | план | охват, карта покрытия, нерешённое |
| `run.md` | прогон | прогоны и карта последнего |
| `fails.md` | прогон | провалы; только дописывается |
| `fixes.md` | находки | причины, фиксы, регрессии |

## Находка

Определение одно на весь цикл, им пользуются все шаги.

**Находка — расхождение, устранение которого значимо меняет поведение** (слово пользователя 1 нояб.): поведение продукта — баг кода, или вердикт проверки о поведении — баг харнесса. Только находки чинятся и держат цикл. Что находкой не является — `references/findings.md`.

Отсюда же мера сценария и теста: в «Ожидаем» и в проверках — только то, расхождение с чем было бы находкой.

## Круги

- Повторяются выкладка, прогон и находки; гоняются только сценарии, которых коснулся фикс.
- Ошибка самого сценария или скрипта — правишь и прогоняешь его; полного круга нет.
- Находка вернулась после фикса — причина не устранена: назад к фактам.
- Число находок от круга к кругу не падает — меняешь подход, а не делаешь ещё круг.

## Итог

Тому, кто позвал, — пользователю или deliver:

- **План:** охват, флоу, сценарии; сколько дописано слепым расширением; нерешённое с закрывающими вариантами.
- **Тесты:** покрыт, улучшен, добавлен, дубликат убран — числами; тестов и дубликатов до и после.
- **Прогон:** PASS / FAIL / SKIPPED на первом и последнем круге.
- **Находки:** харнесс и код, все закрыты; причина — одной строкой каждая. Не-находки — числом по видам.
- **Выкладки:** коммиты и версии на флоте.

# Протокол проверки «пары предсказывают забытых близнецов»

Записан до подсчёта исходов: к этому коммиту видны только форма истории и число пар в снимках, ни один близнец не считан. Определения счётчика — здесь; после прогона меняются только ошибки кода, и каждая такая правка называется в итоге.

**Вопрос.** Предсказывают ли подтверждённые пары дублей забытых близнецов лучше, чем размер и число коммитов?

**Вход.** Вся история: ветки и remote-ветки на момент заморозки, кроме `proof-*` (хэш списка 33ad672ce012d920). Точки c3949ab, 106e8e6, 5e1ac6d. Детектор — `scan.mjs` этой ветки, один для всех точек, на чистой копии коммита. Окно точки — потомки точки до замороженных вершин. Пары: `near` и `inside`, кроме `scripts/`. Вторые — снимочные скрипты, скачки уже описаны в сигналах.

## Определения

| понятие | правило |
|---|---|
| правка поведения | лексемы функции (параметры и тело) изменились без комментариев, пробелов, типов, `as`, `!`; локальные имена канонизированы, то есть переименование локальной — не правка; строки и текст JSX — поведение |
| задача | отрезок истории без развилок и слияний; разрыв больше 60 минут режет отрезок |
| слияние | правки не даёт, только двигает слежение |
| массовый коммит | больше 12 файлов кода без тестов (порог уже стоит в `scan.mjs`): правки не даёт, только двигает слежение |
| перепись | Жаккар формы до и после (шинглы 5 нормализованных лексем) < 0,3: правки не даёт, считается отдельно |
| связь порвана | функции нет: ни в своём файле, ни в изменённых файлах коммита по имени или форме (Жаккар ≥ 0,5) |
| копии правки | одна и та же смена функции (та же сторона, то же до, то же после) на разных ветках считается один раз |
| движется | у пары есть хотя бы одна правка поведения или перепись |
| синхронно | обе стороны правлены в одной задаче |
| односторонняя правка | одна сторона правлена в задаче, другая жива и в этой задаче не правлена |
| поздняя пропагация | односторонняя правка, и другая сторона в другой, более поздней задаче получает такую же: Жаккар шинглов (по 3) добавленных и убранных лексем ≥ 0,5 |
| сближение | односторонняя правка без поздней пропагации подняла текстовый Жаккар пары: это вторая половина чужой правки, начало которой раньше окна. В забытых не считается, показывается отдельно |
| расхождение | односторонняя правка, не поздняя и не сближение, вторая сторона жива на момент правки |
| забытый близнец | поздняя пропагация + расхождение; единица — эпизод: пара и односторонняя правка. Рядом — число разных правок без повторов по парам |

Точность: 20 случаев, случайный выбор с зерном 20261106, 10 поздних и 10 расхождений (поздних меньше — все). Читаю дифф и обе функции. Формальная точность: правка поведения есть, вторая сторона её не получила в задаче. Содержательная: стороны — одно правило, и правка относится ко второй стороне тоже.

## Предсказание

**Подтверждённая пара** — основная метка: слепой читатель, агент с нуля, видит только тексты двух функций на точке и не видит истории, исходов и цели проверки. Вторая метка: сопоставление с `labels.md`. Она размечена 6 нояб. на 5e1ac6d, колонка расхождений там написана после всей истории, поэтому она с утечкой и идёт только в сравнение.

**Основной тест — пары, точка 106e8e6.** Там есть и окно, и нет перепись всех модулей подряд. c3949ab — повтор. 5e1ac6d — только счёт: окно около трёх часов.

- Единица: пара сканера. Все пары могут дать исход, поэтому число пар не задаёт исход по построению.
- Исход Y: эпизоды забытого близнеца на пару.
- Признак: подтверждена (0 или 1).
- База: сумма строк кода двух модулей; сумма коммитов двух модулей до точки; размер пары в лексемах. Сравнение — с лучшей из трёх после подсчёта, это в пользу базы.
- Мера: ранговая корреляция Спирмена, разница с лучшей базой, 95 % интервал бутстрепом с кластерами по паре модулей, 2000 повторов, зерно 20261106.

**Второй тест — модули.** Исход Y2 не зависит от списка пар: одна и та же добавленная строка кода (от 30 знаков без пробелов; не импорт, не комментарий) пришла в модуль M2 в задаче позже, чем в модуль M1; в M2 её раньше не было, из M1 она в этот коммит не ушла. Единица: модуль на точке. Признак: число подтверждённых пар модуля. База: строки кода модуля, коммиты модуля до точки. Мера та же, бутстреп по модулям.

## Порог решения

| исход на основном тесте | вывод |
|---|---|
| ρ признака выше лучшей базы, нижняя граница интервала разницы > 0 | лучше базы |
| разница > 0, интервал задевает 0 | данных мало, победы нет |
| разница ≤ 0 | не лучше базы |
| пар с исходом меньше 10, или подтверждённых пар с исходом меньше 5 | данных мало, что бы ни показал ρ |
| содержательная точность счётчика ниже 0,5 | исход шумит: числа показываю, вывод «данных мало», пока эпизоды не прочитаны руками |

Второй тест основного вывода не отменяет: совпал — подкрепляет, разошёлся — так и пишу.

Метки и случаи поимённо (machineOf, кадр без callsign, пустой id, строка журнала) считаю чтением истории, не счётчиком: они короче порога детектора.

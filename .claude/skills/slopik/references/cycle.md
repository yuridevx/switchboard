# Цикл

Цикл живёт в файлах, а не в процессе. Его ведёт старший: сессия, вызвавшая `/slopik` без аргумента. Сессия кончилась — следующая продолжает. Цикл никого не ждёт.

## Где что лежит

| что | где | кто видит |
|---|---|---|
| ветка сборки `slopik-cycle` | свой worktree | все |
| `config.json`, реестр, именные, книги домов | `.claude/slopik/` | все |
| снимки пар, журнал проходов, метка прохода | `SLOPIK_HOME`, по умолчанию `~/.slopik` | старший и ретро; числа не идут в задание слопика |

Занятая ветка — это замок: `git worktree add` не отдаст `slopik-cycle` второму старшему. Не вышло — цикл уже ведут, выходи.

`.claude/slopik/config.json`: `houses` — команда, печатает `[{name, dir}]`; `ignore` — выражение путей вне счёта. Конвейер — `node <скил>/scripts/census.ts census | snapshot <имя> | fate <до> <после> | pass <json> | stop`. Команды из корня ветки сборки.

## Дневной проход

```
устав с диска → незавершённые ветки → перепись → очередь → снимок до
слопики, по одному на цель, свой worktree от ветки сборки
приёмка → слияние → снимок после → судьбы → pass → stop?
```

- **Очередь.** Цели из `wake`, новых пар, заявок и чётких багов бэклога: открытые двери, потом баги, потом следы вне владельца, потом движущиеся пары. Оставленное в книгах дома выбрасывается; заморозка — только заявка. Правка будит хозяина посмотреть, рядом ли она с его понятиями: нет — цели нет.
- **Волны.** `waves <json>` раскладывает очередь `[{id, houses}]`: в волне цели без общих домов, не больше `slots`. Цель вписывает все дома, которые тронет, включая потребителей и номера версий. Волна идёт разом, следующая ждёт её конца.
- **Слопики.** В обычном режиме один агент на слопика на всю итерацию: следующая цель — обращением к нему, в том числе параллельно с другими слопиками. На входе скил, привязка, устав именного и книга, без чисел. Слопик гоняет только свою границу и потребителей; своя книга и свой worktree не мешают соседям.
- **Пул.** Worktree принадлежит слоту, а не слопику: `slopik-<слот>`, столько, сколько слотов. Новая цель — `git checkout` ветки цели от ветки сборки в свободном слоте; зависимости остаются, ставятся заново только при смене lock-файла. Обычный слопик между целями держит не worktree, а агента и книгу. Пул живёт между циклами и не растёт.
- **Очередь слияния.** Параллельны слопики, а не слияние: старший принимает ветки по одной, в порядке готовности. Конфликт правит слопик на свежей ветке сборки. Полный прогон — один на волну, после последнего слияния: падение ищется делением ветки сборки.
- **Приёмка своими руками.** Дифф проверок и тестов, откат тестов: `git checkout <до> -- <тесты>` и прогон на новом коде, тесты границы и потребителей, потом слияние и прогон в ветке сборки. Красное — стоп.
- **Судьбы.** `fate <до> <после>` сразу после слияния, до записи реестра и судеб: иначе своя запись выглядит как правка контроля. Пара из `read` ушла из отчёта, а копия жива: читать. Запись `signs` — обход, пока чтение не покажет иное.

| судьба | значит | считается |
|---|---|---|
| слита | одно определение, вызовы к владельцу | успех |
| оставлена | причина записана | нейтрально |
| опыт | операция в своей ветке, не для выпуска | не считается |
| различие открыто | совпавшее сведено, различие ждёт ночи | открыто |
| исчезла, логика на месте; перемещена; обёрнута | детектор молчит, копия жива | обход |
| удалена с поведением | вместе с дублем ушло поведение | потеря |
| новая | появилась после работы | итог |

## Ночной проход

Глубокий режим: качество дня, один раз за ночь или по слову. Все роли и слопики работают вслепую, с нуля; книга у них на входе.

1. **Свежий читатель** по дневным сведениям: старое рядом с новым, полная таблица, опыт на обеих копиях. Потеря — красный тест и правка.
2. **Архитектор** решает открытые различия: какое значение остаётся, менять ли эталон «чьё: код». Что закрепил человек, не меняет. Сводит следующий день.
3. **Ревизор** читает подозрительные судьбы, случайную долю сведённых и новые записи «оставлена» в книгах: вердикт слопика о своей паре сам себя не закрывает. Обход — работа снимается, случай на страницу. Перенос кода `fate` не видит: при операциях над домами сравнивай тесты и дома.
4. **Выпуск** — по привязке.
5. **Ретро** и страница итога. Счётчик `twins.ts <до> <после>` даёт кандидатов на чтение, а не метрику: на истории он не обошёл размер, зато и исхода почти не было. Решает накопленное.

## Население

Числа проходов и порогов нет: пустой проход — и дом спит до события.

| событие | условие | старший |
|---|---|---|
| рождение | модуль без строки (`born`) | фраза дела при первом пробуждении |
| пробуждение | правка рядом с понятиями, след вне владельца, новая пара, заявка, ошибка из журнала | цель в очередь |
| сон | ход без находок | ничего |
| отказ приёмки | работа отклонена | один раз заново другим агентом; второй отказ — цель на страницу, дом спит |
| обход | судьба обхода или правка проверок | работа снята, как отказ |
| деление, слияние | признаки из скила | вердикт архитектора, исполняет слопик |
| уход | `gone` | понятия и заявки передаются, строка удаляется |
| именной | `orphaned`, граница, снятие | только человек, цикл пишет на страницу |

В споре за понятие решает реестр; граница именного выше вольного; два именных заявили одно — вопрос на страницу.

## Остановка

`stop` отвечает «нет»: лежит `SLOPIK_HOME/stop`; очередь пуста; проход без подтверждённых; приёмка отказала два прохода подряд.

Штатно: новых целей нет, агенты доводят шаг, ветки остаются, журнал записан. Обрыв — ожидаемая ветка: следующий старший начнёт с незавершённых веток.

Остановка цикла — не конец системы: `/loop /slopik` снова делает перепись. Событий нет — пустой ход. Ритм ведёт ретро.

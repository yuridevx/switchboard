# Слопики в Switchboard

Порядок — в скиле `slopik`; здесь — чем его шаги делаются в этом репо и где оно кусается. Устав и персона архитектора стоят выше обоих.

Контекст выпал или работа незнакома — первым читай `.claude/slopik/chronicle.md`: решения пользователя, исследования, проверки и выводы.

## Где что

| что | где |
|---|---|
| дом | модуль с `module.json`; `scripts/houses.ts` этого скила печатает их для конвейера |
| реестр, книги, именные, `config.json` | `.claude/slopik/`. Книга лежит вне папки модуля: иначе правка книги меняет хэш архива выпуска |
| бэклог | `backlog.md` в памяти проекта и `.claude/slopik/backlog.md`; запись называет файл — значит, дом известен |
| пул worktree | `.claude/worktrees/slopik-<слот>` основного дерева, не внутри другого worktree |
| `slots` | `config.json`; по умолчанию половина ядер |
| Go | `scripts/gofuncs.go` этого скила — команда `scan` в `config.json` |
| детекторы | `jscpd` 5.4.2, папка `~/.slopik/tools`; замеры — `references/detectors.md` |
| настоящие потери прошлых сведений | `references/divergence-history.md` — строка к строке с таблицей расхождений |
| страница итога | Artifact; комментарии читает постоянная сессия цикла |

## Чем проверять

| что | команда |
|---|---|
| тесты Worker-модуля | `npx vitest run` в его папке |
| тесты Host | `npx vitest run host` |
| фронт | тесты пакета, `node scripts/web-typecheck.mjs`, снимки тронутых экранов |
| типы Worker-модулей | `npx tsc -p tsconfig.json --noEmit` в папке каждого: корневой `tsc` их не видит |
| приёмка | `npm run gate`, потребители, чистая копия Linux, keeper с `-race` |
| свежий читатель ночью | `node tools/demolish/cli.ts lost <база> [--comments] <пути>` — вывод читается целиком |

## Где кусается

- **Ветке нужен свой `npm ci`.** Без него импорты уйдут в основное дерево, и прогон ничего не докажет.
- **Номера версий** поднимает слопик. Код `gate` входит в архив Host, поэтому правка контракта `gate` поднимает и ядро; остальное называет `release check` до push.
- **Номера эталонов** — следующий свободный в файле теста; столкновение разводит старший при слиянии.
- **Уход и слияние дома — через живой каталог «Выпусков».** Старая версия рядом с новой даёт двух владельцев MCP-сервера: сессия не поднимается, а манифесты этого не видят. Выпуск — с `without`.
- **`scan.mjs` не считает `scripts/flow-*`**: их клоны видит только `jscpd`.
- **Повторы** сверяются с закрытым списком веток восстановления устава: повтор вне списка — цель.
- **Параллельность.** Устав: в одних файлах не больше двух исполнителей; волны держат ноль общих домов.
- **Сеть base1 и base2** не дебажится: обрыв там — не повод для цели.

## Роли здесь

- **Обычный режим:** агент один на итерацию, следующая цель — `SendMessage` к нему.
- **Архитектор:** агент `architect` с нуля; вход — понятие и различие, а не только дизайн и дифф.
- **Род «работа»:** дома нет. Ночной ревизор читает устав и скилы; цель — правка скила. 🔒 он не правит — только помечает на странице итога.
- **Протокол и хранилище** ведут именные Почтарь и Хранитель; формат меняется автономно, через слепого архитектора. Особое задание Почтаря — меньше имён контракта при тех же фичах.
- **Эталоны:** архитектор может сменить эталон с пометкой «чьё: код»; 🔒 и слово пользователя — нет (устав).
- **Заморозки сейчас нет.** Часть, занятая другой сессией, — заявка, а не правка. Первая цель — кадр без `callsign` в `logins` и `profiles`.

## Автономия

Слово пользователя 6 нояб.: всё, кроме прода, — полная автономия; прод — только его слово. Сейчас не-прод — это тестовый флот.

- **Выпуск ночью.** Ветка сборки сливается и выкладывается на тестовый флот партией. Перед этим цикл спрашивает живые сессии репо, кто выкладывает и какие номера заняты (устав). Занято — партия ждёт следующую ночь; цикл не стоит.
- **`main`** цикл сливает сам — после приёмки и зелёного тестового флота.

## Запуск

Запускает пользователь: `/loop /slopik` в постоянной сессии. Позже запускать будет пульт. Планировщик ОС цикл не ставит.

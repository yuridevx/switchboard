# Артефакт

Результат работы — сайт флота, а не текст в разговоре: у него постоянный адрес, человек комментирует прямо на странице, комментарии приходят тикетом. Источник сайта — папка в репозитории; на сайте руками ничего не правится.

## Круг

1. **Папка.** Страница — в своей папке репозитория: `index.html` и то, на что он ссылается относительными путями. Дизайн — `docs/designs/<имя>/`.
2. **Блоки.** Каждый смысловой блок страницы — элемент с `data-block` и своим `id`. По ним человек ставит «просмотрено»; непросмотренный блок панель красит целиком.
3. **Правки.** Изменённое при правке помечается `data-chg="<уникальное имя>"` внутри своего блока: блок с правкой, которой человек не видел, снова непросмотрен. Свой цвет правкам не задаётся — фон даёт панель.
4. **Коммит, потом выкладка.** `site_publish {to: свой позывной, dir, name}`. Имя — одно на всю жизнь страницы: повторная выкладка обновляет тот же адрес. Ответ называет `commit`; `dirty: true` — в папке остались правки вне коммита: закоммить и выложи снова.
5. **Сдача.** Ссылка на сайт и коммит — в вердикте тикета (`ticket_set … verdict: done`) или в ответе человеку.
6. **Комментарии.** Приходят тикетом «Комментарии к сайту …»: у каждого пункта блок, элемент и текст, в шапке — коммит, к которому они писались. Правишь папку, коммитишь, выкладываешь на тот же адрес. Ответ на комментарий — в поле `reply` его строки: `site_db {name, sql: "update sb_comments set reply = ? where id = ?"}`; человек видит его в метке комментария.

## Что есть у сайта

- **Панель** — на каждой странице сама, скрипт подключать не надо. Выключается при выкладке: `comments: false`, `marks: false`.
- **Кому идут комментарии** — `feedback`: пост проекта или позывной; не назван — тебе.
- **Адрес** — выдаётся сам, с секретом: открыть может только тот, у кого ссылка. `address` — назвать адрес вручную при первой выкладке: такой сайт открыт каждому; занятый адрес — отказ `taken`.
- **База** — своя SQLite у каждого сайта. Страница: `await sb.db("select …", ...params)`; ты: `site_db {name, sql, params}`. Данные страницы держи в базе, а не в файлах сайта: их видят все устройства и ты.
- **Удалить** — `site_remove {name}`: адрес и база стираются.

## Страница

Правила страницы дизайна — раздел «Дизайн-документ» устава репозитория. Своих скриптов меток и комментариев страница не несёт: это дело панели.

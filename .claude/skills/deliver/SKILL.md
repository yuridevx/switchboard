# Делай

Принятое становится работающим на флоте, и это доказано числами. Ведёт главная сессия в персоне архитектора. Устав и персона уже в контексте — здесь только порядок, команды и ловушки, которых в них нет.

Проверяет и выкладывает CI. Сессия пишет код и одну свою проверку; на флот с компьютера сессии ничего не идёт.

```
код + своя проверка → push, PR → проверка CI → main → тестовый флот: выкладка, живой список → fleet/test → «в прод» → fleet/prod
```

## Готово, когда

- каждая строка «Готово» доказана прогоном CI: число до и после, ссылка на прогон;
- открытых находок 0;
- второй проход сделан: хвосты, меняющие поведение, доделаны; дубликатов, лишних коммуникаций и циклов 0;
- итог сдан.

## Вход

Работа начинается со строк «Готово»: без них нечем доказать конец. Строка называет проверку — эталон или живой шаг — и число.

| запрос | откуда строки «Готово» |
|---|---|
| «делай» по дизайну | блок «Порядок реализации» принятого дизайна |
| «делай» по плану из разговора | пишешь сам по плану |
| «поправь», «поработай над» | сначала диагностика — факты из журнала, причина, слой и нарушенный инвариант; потом строки по ней |

План правки, которого не было в принятом дизайне, проходит гейт персоны до первой строки кода: дубликат дешевле не написать, чем сводить.

Число «до» — из итога последнего прогона main: `gh run list --branch main --limit 3`, сводка на странице прогона. У себя его не снимают.

## Код

Порядок — по зависимостям, от стабильного: protocol → Worker-модули → ядро Host → модули Host → web → keeper.

У себя сессия запускает одну свою проверку — ту, что пишет сейчас:

| своя проверка | команда |
|---|---|
| файл теста | `npx vitest run <файл>` в папке пакета |
| снимок тронутого экрана | страница на моке: `npx vite --port <порт> --strictPort` в `web/`, адрес с `?mock`; сценарий — свой `shots.mjs` |
| свой живой шаг | файл одной живой проверки, например `node tools/fleet/live-files.mjs test cli wsl` — после того как CI выложил main |

Правило импортов, типы, пакет целиком, все тесты и живой список целиком сессия не гоняет: это делает CI на каждый push. Пакет целиком, когда без него не разобраться, — `node tools/test/run.mjs <часть>`.

## Выпуск

Коммит, push и слияние входят в «делай» — отдельного слова не ждут.

1. Коммит своих путей → push → `gh pr create` → `gh pr merge --auto --merge`. Зелёный PR сливается сам; красный main не принимает.
2. Красная проверка: `gh run view <номер> --log-failed` → правка → push.
3. Слияние запускает выкладку на тестовый флот (`deploy`): выкладывается только изменившееся — по отпечатку кода, в порядке платформа → службы со страницей → машины; затем живой список `tools/fleet/live.mjs`.
4. Зелёный список двигает ветку-метку `fleet/test`. Красный — правка следующим PR; отката main нет.

Пока идёт CI — второй проход, не ожидание.

Что где стоит:

```
git fetch origin
git log --oneline origin/fleet/test..origin/main         # слито, ещё проверяется
git log --oneline origin/fleet/prod..origin/fleet/test   # уйдёт в прод
node tools/deploy/fleet.mjs test cli --plan              # какие части отличаются от того, что на флоте
```

Ловушки:

- Новая функция добавляет свою живую проверку строкой в список `tools/fleet/live.mjs` — иначе её никто не запустит.
- Проверки списка идут одновременно. Своя проверка не рассчитывает, что на машине она одна: сверяет свои сессии, а не все; адресата инструмента называет в просьбе. Перезапускает Host или трогает вторую машину — дорожка «шумная»; меняет общее для флота — «одна». Длиннее полутора минут — делится на части (`SB2_PART`), каждая со своими сессиями.
- Время пути: проверка PR — около 1,5 мин, выкладка с живым списком — около 3 мин. Стало заметно дольше — это находка.
- На тесте всегда main: правка живого поведения идёт слиянием, а не выкладкой ветки.
- Основное дерево общее с другими сессиями — работаешь в своём worktree; `npm ci` — в нём же.
- Сломан инструмент выкладки или живая проверка — правка тем же путём, через PR.

`test-cycle` — по слову пользователя или когда меняется поток между частями.

## Прод

Только по слову пользователя: `gh workflow run deploy.yml -f fleet=prod`. На прод идёт ровно коммит `fleet/test`; зелёная проверка двигает `fleet/prod`. Сессии до и после и номера отката — в итоге прогона.

Закрыт, когда прогон зелёный и `git log origin/fleet/prod..origin/fleet/test` пуст.

## Слепой архитектор

Только по слову пользователя («слепой архитектор», «пройдись архитектором» по диффу): новый агент `architect` на дифф — коммиты или пути и охват. Код правишь по его отчёту ты; находок гейта после — 0.

## Второй проход

Один: принятое и гейт персоны против результата. Что делать с хвостами — правило устава. Хвост идёт тем же путём: push, проверка, тестовый флот.

## По ходу

- Смена шага — одна строка пользователю: что сделано, что дальше.
- Шаг пропущен — одна строка с причиной сразу, не в итоге.
- Факт противоречит принятому — решение пользователя не меняешь: делаешь закрывающий вариант, развилка идёт в итог.

`<scratchpad>/deliver/<slug>/plan.md` — рабочая память на случай сжатия контекста: строки «Готово» с числами до и после и статусом, отложенные половины, решения развилок одной строкой.

## Итог

- **Готово:** строка → проверка → число до и после → ссылка на прогон.
- **Гейт:** дубликаты, лишние коммуникации и циклы до и после второго прохода; слепой архитектор, если был, — находок до и после.
- **Выпуск:** прогон выкладки, что выложено, живой список числами; итог test-cycle, если был.
- **Развилки:** решённые — одной строкой; задевшие решение пользователя — с закрывающим вариантом, который сделан.

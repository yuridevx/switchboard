# Прогон плана

Цель: узнать по факту, ведёт ли себя работающая система так, как написано в плане.

## Вход

Папка плана `<scratchpad>/testplan/<slug>/` или путь к страницам флоу того же вида; можно подмножество сценариев. Плана нет — отказ с причиной.

## Где гоняется

- Где требуют «Подделки» сценария: стенд с подделками на границе или выложенный тестовый флот.
- В тестовом флоте — только свои сессии и модели попроще; чужие сессии не трогаешь.
- Все команды в живую систему — от одного исполнителя.
- Секреты — из `~/.switchboard-dev` или env, через stdin, не через argv.

## Свойства прогона

- Каждый сценарий начинается с чистого состояния: следы прошлых сценариев на его исход не влияют.
- Шаги идут через публичные входы системы, исход читается по наблюдаемому — тому, что названо в «Ожидаем».
- Исход сценария — один из трёх:
  - **PASS** — каждое «Ожидаем» подтверждено;
  - **FAIL** — хоть одно опровергнуто или не наблюдается;
  - **SKIPPED** — только когда план сам держит сценарий в нерешённом или границу нельзя поднять; причина записана.
- «Не удалось понять» не бывает: наблюдать не вышло — это FAIL, в доказательстве — почему.
- Система не поднялась — прогон останавливается, FAIL с причиной.
- Прогон ничего не чинит: план, код, тесты и стенд не правит.

## fails.md — FAIL

Рядом с планом. Только дописывается, записи не правятся. Тот же FAIL в новом прогоне — новая запись: повтор тоже факт. Находка ли FAIL — решает solo-bugtriage.

```markdown
## FAIL 007 — <flow-id> · <сценарий>
- Прогон: <номер> · <время UTC> · где: стенд | тестовый флот
- Ожидаем (из плана, дословно): …
- Наблюдали: …
- Воспроизвести (от чистого состояния): <команды>
- Доказательство: вывод, коды выхода, строки журнала — дословно
- Код: <файл>:<строка> — вход и ссылки страницы
```

## run.md — итог последнего прогона

- Числа: флоу, сценарии PASS / FAIL / SKIPPED.
- Карта: флоу × сценарий → исход, номер записи FAIL.
- Пропущенное — с причинами.

Готово, когда у каждого сценария есть исход, а у каждого FAIL — запись.

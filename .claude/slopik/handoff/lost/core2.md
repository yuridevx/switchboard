## Потери

1. **initialize отказан, процесс жив.** claude на негодный initialize отвечает control error и ждёт дальше (в файле claude: `lt(q,"initialize: ...");continue`). Старый код снимал процесс, новый ждал его выхода без предела. Снаружи: open не отвечает, сессия навсегда starting, ready не приходит, Host не отвечает на этот запрос до остановки. Тест «initialize отказан, процесс жив» — красный: Test timed out in 30000ms. Правка e84b5c8.
2. **Разговор в папке другого проекта.** Настоящий claude: `--resume` в чужой папке — «Not logged in» (нашёл), разговора нет нигде — «No conversation found». Настоящий getSessionInfo: с dir — нет, без dir — найден. Откат из окна точки в другую папку: файл кладётся в выбранную, прежняя копия уходит в сторону, session.start с point шёл через проверку с dir — новый пустой разговор с тем же id, молча. Тест «разговор лежит в папке другого проекта» — красный: options без resume. Правка 99ad6b0.
3. **Ответ модуля не в JSON.** Отказ цепочки ответа без catch: unhandled rejection, main выходит с кодом 1. Один запрос ронял Host, повтор — второе падение, keeper ставит failed. Красный: Unhandled Rejection TypeError: Do not know how to serialize a BigInt. Правка 9196336: строка журнала, спросивший получает timeout, как в старом.
4. **Предел host.cli.** Linux, настоящий claudeCli, потомок держит вывод: предел 500 мс, ответ через 6115 мс; после правки 509 мс. На Windows close приходит сразу: тест там зелёный и до правки, красный опыт — на wsl. Правка 793d6ea.
5. **package.json модуля.** Чтение вне try: отказ всего выпуска, Host не стартует. Упаковка package.json не требует, keeper host --check не зовёт. Красный: ENOENT из loadRelease. Правка 69b3163.

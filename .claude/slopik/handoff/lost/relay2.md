## Группы

### 1. Причина отказа текстом: `fleet.ts`, `to` и `part` — ПОТЕРЯ
Было: `JSON.stringify(f.to)`, `JSON.stringify(f.part)`. Стало: подстановка в шаблон, объект с `toString` бросает, `guarded` роняет объект (e2, e2b, e3). Коммит `e0e2dd0`.

### 2. Предел пропуска в журнале: `.slice(0, 80)` — ПОТЕРЯ
Строка lost 177. На открытой двери длину выбирает чужой (e5). Коммит `c99a798`.

### 3. `String(f.key ?? "")` — не потеря, открытая дверь, ПРАВКА
Лишний `?? ""` пропал без вреда (e1b). Сам `String()` ронял объект и в старом коде (e1): человек без пропуска. Бриф: на открытой двери отказ словом обязателен. Коммит `a248b76`.

### 4. `from=${f.from}` — не потеря, граница доверия, ПРАВКА
Падало и в старом коде (e4). Коммит `2d2f25d`.

### 5. Роль из адреса вместо `kind`: `own`, `kind`, `previous`, `c.kind` — то же другими именами
`fleet.ts`: `mine` строка 198, `rivals` строка 231, `roster()` строка 138, `spread()` строка 145. Проверено по схеме gate: `addr` считает база, `@имя` у host и `имя~человек` у client; `PERSON` не пускает `~` и пробел, `PASS` — только host и client. Других видов адреса нет.

### 6. Закрытие прежнего кода — то же, новое поведение лучше
`closePreviousCode` → конструктор, `drop`. Фильтр `readyState === OPEN` снят: e7 — сокет, закрытый во сне, не ломает старт, машина получает `machine.left`, которого старый код не писал. Запись, правки нет.

### 7. Карточка и `card()` с проверкой `ver` — снято
Проверка версии на каждом событии обслуживала сокеты, которых нет: конструктор снимает всех прежних до первого события; проверено тестами 3124, 3138.

### 8. Порядок проверок в `onFrame` — запись, вреда нет
`session.state` и `hello`/`roster` проверяются раньше `from`. Видно только своему Host: e10 — чужой `from` принят и отброшен, в запись не идёт; для `hello`/`roster` меняется слово с bad_from на bad_frame. Настоящий Host `from` в этих кадрах не шлёт: запись сессии кладёт его в поле `by` (`session.ts` строка 98).

### 9. `to: []` у relay — запись
Было `offline` строкой журнала, стало bad_frame строкой журнала. Ответа нет в обоих: кадр без id.

### 10. POST мимо корня — запись
`req.method === "POST"` без `pathname === "/"`. e9: тот же пропуск, тот же отзыв, власти не прибавилось. 426 сменился отказом словом.

### 11. `!kid` — запись
`kid: ""`: bad_request сменился на unknown_key (e9). Отказ словом есть, строка в базе не тронута.

### 12. Журнал: тексты строк — то же другими словами
`relay_updated`, `offline`, `revoked`, `abort`, `hello`, `close`, `replaced`. Поиск по `scripts`, `tools`, `host/core/src`, `web/packages`: разборщиков нет. Адрес отозванного остался в строке `revoke` у `index.ts`.

### 13. `limited` по объекту против одного `within` на всех — то же
Предел тот же; один молчащий объект и там и там даёт `failed`, это чтение кода: тест держит только молчащий gate (`revoke-hang`).

### 14. `link`: опции `requestMs`, `pingMs`, `maxPauseMs` — снято
Поиск по `host web tools scripts workers`: ни одного потребителя.

### 15. `link: нет WebSocket` — снято
Host — Node ≥ 24 (`engines`), страница — браузер: `WebSocket` есть всегда, стенд передаёт свой.

### 16. `link.request`: запись ждущего после `send` — снято
`cf76970` поставил запись раньше отправки, случая не назвал. Настоящий WebSocket не доставляет ответ внутри `send`: `message` — отдельная задача цикла событий. Подделки потребителей тоже: тесты `host/core` и `web/packages/core` зелёные.

### 17. `link`: `backoff` → `nextPause`, `live` → `s === ws`, `stopTimers` → `detach`, `isFinal` → `onClose`, `setState` → `become`, `settle` → `finish`, `abandon` → `cut`, порядок `open` и снятия ждущих — то же другими именами
Прочитано по веткам: `link.ts` строки 76–114, 116–132, 177–182. Сброс паузы на каждом roster вместо перехода в open — исход тот же: пауза берётся только при обрыве.

### 18. `isReply(f)` против `f.type !== "reply"` в `send` — снято
Различаются только ответом без id или `ok`: своих таких ответов клиенты не шлют.

### 19. `fleet-client`: `join`, `home`, `routeOf`, `sendBy`, `sendList`, `refusal` — то же другими именами
`open` строка 50, `main` строка 69, `route` строка 111, `through` строка 121, список — строки 142–150. `why` у timeout теперь с адресом вместо типа кадра. Читатель один — текст отказа инструмента fleet (`tools.ts` строка 22), разбора нет: сессия видит другую фразу с тем же смыслом.

### 20. `closed` в `join` — снято
После `close` кадров нет: `link.close` снимает сокет, `listMachines` проверяет `closed` сам.

### 21. `to: []` у клиента: `send` отдаёт `undefined` — снято
Было `{ok:false, error:"offline"}`. Вызовы со списком — три, все проверяют длину: `chat.ts` строка 66, `ask.ts` строки 49, 65; инструмент `send` держит `to` строкой, страницы списком не шлют. Настоящий поток не доходит.

### 22. `protocol` — то же
`oversize` без короткого пути: исход тот же, цена — кодировка на каждой отправке, замеров против нет. `parseFrame`: те же входы отвергаются, тест 2003. `ok`: `result: undefined` не доходит до провода, `"result" in` не ищет никто. `reaches`: `userOf(device)` даёт `~почта` только у человека и устройства, значит условия равны.

### 23. Комментарии — 48 строк
Пропавшие описывают то, что есть в коде другими словами, или снесённое: `Bare`, `Member`, `closePreviousCode`, разделители. Единственный с содержанием — «Браузер и Node принимают только код 1000 или 3000–4999»: вызовы `close` в репо — только 1000 и 4000.

## Оставлено без правки

- `callsign ${callsign}` в `onSessionState` бросает так же, как группа 1, и было так в старом коде. До строки доходит только свой Host машины, гостям отказ раньше: граница доверия не пересекается.
- `bad_frame до hello · ${f.type}` пишет тип кадра от чужого без предела, и было так в старом коде. Отказ словом есть.
- Сокет без `hello` живёт без предела, и было так в старом коде. Не потеря.

## Потери

1. push.send, порядок. Вход: подписки нет или все устройства в skip, notify не влезает без body. Настоящий поток: chat/ask.ts:69 кладёт текст вопроса в кадр каждой кнопки, длинный вопрос с вариантами превышает 4 КБ в actions. Красный: `expected [ { type: 'reply', id: 'h-1', …(3) } ] to match object [ { ok: false, error: 'gone' } ]`. На 106e8e6 тест зелёный.
2. Кнопка уведомления, сбой до relay. Красный: `Error: база закрыта` из click, уведомления нет. На 106e8e6 тест зелёный.

## Снято опытом

1. Ключи. Красные были: `InvalidCharacterError: atob() called with invalid base64-encoded data` на "AAAAA"; bad_frame на ключах с «=». Коммит 3241e8e откатан. Причина: ключи приходят из PushSubscription.toJSON() и scripts/flow-more.ts:52 без заполнения. Предел: настоящие браузеры здесь не проверены.
2. getSubscription отказал при старте. Красный: `"web-alerts": "Модуль web-alerts упал на старте: Error: AbortError"`. На старом — ask. Причина: настоящего потока с таким отказом нет; исход — ветка устава «ошибка модуля — модуль выключен», причина видна. Предел обработчика держит 6990.
3. Две проверки строки разом. Красный: `expected false to be true` на disabled. Причина: нужно нажатие человека между двумя ответами чтения, идущими в одно время; исход — кнопка активна до конца включения.
4. Показ и запись параллельно. Опыт на idbStore с fake-indexeddb, нажатие в следующем ходе: тест зелёный, пометка clicked на месте. Транзакции readwrite идут по порядку создания. Не воспроизвелось, код не тронут.

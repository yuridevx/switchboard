# Switchboard — устав репозитория

🔒 **Switchboard — независимая экосистема модулей и сервисов, которые пользуются друг другом. Не одно решение.** Монорепо четырёх типов: Worker-модули на Cloudflare, приложения для ОС, приложение Claude SDK (Host) со своими модулями и веб-приложения. Первый набор — рация из всех четырёх типов: сессии Claude Code на разных машинах и в разных аккаунтах видят друг друга, переписываются по callsign и достают до телефона. Switchboard заменяет claude-fleet (Пульт и Смотритель): все его функции — модулями экосистемы по её принципам (слово пользователя 31 окт.).

**Сейчас этап реализации** («делай» — слово пользователя 31 окт.: реализовать, покрыть тестами, задеплоить и проверить вживую на Windows и WSL).

> 🔒 **Жирный текст после 🔒 — суть, принятая пользователем. Не перефразируй, не сокращай и не смягчай её. Меняй только по прямой просьбе пользователя.** Пояснения после неё можно уточнять, если суть не меняется.

## Раскладка

| папка | тип | что это |
|---|---|---|
| `workers/<имя>/` | **Worker-модули** | Каждый — отдельный Cloudflare Worker, деплоится и падает сам по себе; у каждого свой адрес (прямой POST кадра с пропуском) и свои записи — база D1 модуля во флоте. `workers/relay/` — **Relay**, транслятор рации: объект на машину (`/m/<машина>`) — соединения её Host и keeper и гостей, roster, доставка по `to`; на диск не пишет. `workers/gate/` — пропуска участников (`роль.имя.номер.секрет`): приглашение, приём, отзыв, verify. `workers/releases/` — «Выпуски»: каталог модулей в R2, сборки приложений под именем флота, stable и планы машин. `workers/push/` — веб-пуши (разложение — слово пользователя 31 окт.). `workers/points/` — реестр точек сессий (блоки — в R2), `workers/ledger/` — журнал флота, `workers/github/` — токены приложения GitHub, `workers/prefs/` — настройки людей и страниц в трёх областях (почта, весь флот, приложение): значений не читает. `workers/rooms/` — чаты Telegram как устройства людей: чат — пропуск gate, сессия — тема, ответ человека — кадр в Host через relay. |
| `os/<имя>/` | **приложения для ОС** | `os/keeper/` — **Keeper**, Go, служба ОС: исполняет план машины от Worker «выпуски» — держит Host и приложения через держатели, отвечает keeper.state, подменяет себя. Сам ничего не решает. |
| `host/` | **приложение Claude SDK** | **Host**, Node + Claude Agent SDK, один на машину: ядро `host/core/` и модули `host/modules/<имя>/`; сборка — ядро и модули каталога по её `build.json`. Единственная точка к сессиям. |
| `web/<имя>/` | **веб-приложения** | Каждое собирается и деплоится само. `web/phone/` — телефон, `web/pult/` — пульт (свои экраны — `web/pult/modules/`): два приложения с разным фокусом и общими компонентами (слово пользователя 31 окт.) — пакетами `web/packages/<core\|ui\|view\|board\|card\|chat\|ask\|alerts\|inbox\|labels>/`; `view` — рантайм React (`web-view`), одна копия на странице, `ui` — набор компонентов и основание стилей (`web-ui`). Страницу собирают «Выпуски»: оболочка, модули одним файлом `m/<модуль>.<версия>.js` под вечным кэшем, адреса relay и Worker'ов — в `build.json`. Экран — компонент в месте `data-module`: граница ошибки и область стилей `@scope`; данные — выборкой `app.use`, чужой экран — `app.Slot`, чужой модуль встаёт в место владельца (`place`, `app.placed`). |
| `protocol/` | | Общий конверт кадра: `type`, `id`, `reply`. Модулей не знает. |
| `tools/` | | `manifest-gate` — гейт манифестов (`npm run gate`); `release` — формат выпуска и каталога (архив модуля, хэш, ссылки, раскладка сборки страницы); `release-cli` — упаковка из монорепо и загрузка в каталог через `releases.upload` пропуском программы (`switchboard release core|modules|keeper`, CI — пропуском `ci`), `release check` — до push сверяет код с каталогом и называет, чей номер поднять; машину ставит сам keeper (`keeper install`, приглашение — stdin); `records` — записи области флота, общие для страниц и агентов (проекты, имена), и цикл правки настроек; `send` — сообщение в сессию от служб компьютера (тревоги, сторожа) ключом клиента, без зависимостей. |
| `scripts/` | | Выпуск Worker-модулей (`deploy-workers.mjs`), живые флоу и эталоны выложенного флота (`flow-*.ts`, `live-etalons.ts`, `smoke-relay.ts`), снимки экранов и жесты настоящего кода в браузере (`shots/`: `npm run shots`, `npm run drag`), сервер дизайна и разработки фронта (`design/`: прототип, `npm run front test|prod` — страница из дерева на настоящем флоте). Секреты — из `~/.switchboard-dev` или env, не из репо. |

Имена: callsign `site@laptop`, machine `laptop`, fleet `home`, slot `main`, attachment — карточка соединения в Relay, module — функция Host, контракт — публичный вход модуля.

Адреса по форме: служба `.relay`, часть машины `.keeper@laptop`, машина `@laptop`, сессия `site@laptop`, пользователь `~email`, устройство `phone~email`; голых имён нет.

Модуль — папка с `module.json` в любом репо: что отдаёт (`provides`), чем пользуется (`uses`) и в какие приложения входит (`into`). Каталог «Выпусков» хранит версии модулей; сборка соединяет модули в приложение; пропуск говорит флоту, кто пришёл.

## Жёсткие запреты

- 🔒 **`~/secrets` не читать.** Можно только `ls -la` и `stat`; из рекурсивных grep/find/rg исключать. Секреты передавать через stdin, никогда через argv.
- 🔒 **`git add -A`, `git add .` и `git stash` в общем дереве запрещены.** Коммить только свои пути.
  - 🔒 **Без машинозависимых путей — в репо, в памяти и в CLAUDE.md.** Пути — от файла скрипта, от корня репо, от `~` или из переменной окружения. Раскладка конкретной машины живёт только в её карточке в памяти.
- Файлы входа аккаунтов Claude и общий `~/.claude.json` без спроса не трогаешь: вход переписывает их на всей машине.

## Как работаем

- 🔒 **Режим задаёт запрос.**
  - 🔒 **«Сделай дизайн» → дизайн, подтверждение пользователя, «делай», реализация.**
    - Предлагаешь одно рекомендованное решение, а не меню; просто и легко. Спрашиваешь только то, без чего дизайн не закончить. Эксперименты для дизайна можно и нужно ставить до «делай» — так проверяются решения и собираются данные; рабочую систему при этом не перестраиваешь.
    - 🔒 **Развилка без ответа пользователя к «делай» решается рекомендованным вариантом (правило пользователя 6 нояб.).**
    - 🔒 **Автономный режим («автономно» в запросе) пропускает дизайны: «делай» им даёт архитектор по своему мнению, без вмешательства пользователя (правило пользователя 1 нояб.).** Решения пользователя архитектор и тут не меняет: работа, которая их задевает, — развилка в итог, работа идёт дальше. Развилку цены отмены он решает рекомендованным вариантом и пишет в итог.
  - 🔒 **«Поправь», «поработай над» → диагностика, план метрик, фаза архитектуры, затем код — сам, без ожидания «делай».**
  - 🔒 **«Почему…?» = диагностика и ответ, без фикса.** Отвечаешь по фактам из журнала. Код не меняешь, пока пользователь не скажет «поправь».
  - 🔒 **«Пересобери» = переосмысли и перепиши артефакт с нуля: сначала обдумай, какие диаграммы, примеры и интерактивные элементы лучше всего передадут суть, потом пиши.**
  - 🔒 **Когда пользователь пишет «переосмысли» — переосмысливаешь всё.** Суть, модель, данные и подачу целиком, включая блоки с меткой «прочитал».
- 🔒 **Со всем кодом работаешь ты, инлайн.**
  - 🔒 **Workflow запрещены (правило пользователя 30 окт.).** Помощники — агентами (Agent), не Workflow. Агент с нуля — там, где нужен свежий взгляд: слепой архитектор, слепое расширение плана тестов, слопики глубокого режима (слово пользователя 6 нояб.); остальную работу шагов делает форк главной сессии (слово пользователя 1 нояб.).
    - 🔒 **На рутинную работу запускай агентов на Opus, а не на Fable (правило пользователя 11 нояб.).**
  - Главная сессия работает в персоне архитектора: работа идёт от её ценностей, гейта и мерки с первого шага (слово пользователя 1 нояб.). Слепой архитектор — агент `architect` с той же персоной, с нуля: режим скилов `design` и `deliver`. Персона — @.claude/architect.md (подключена в устав целиком).
- 🔒 **Ревизор слопиков может перепроверять принятое, со сводкой пользователю (правило пользователя 6 нояб.).**
- 🔒 **Второй проход вместо адверсария.** После реализации — один второй проход: дизайн против результата. Значимые хвосты доделываются один раз, мелкие — нет; после этого пункт закрыт и не переоткрывается.
  - 🔒 **Хвост — только то, что меняет поведение. Переименования и неточности в документах — редакторские правки, их не делаешь.**
- 🔒 **Задачи не бросаешь недоделанными. Надо отложить — разбиваешь на две: первую закрываешь, вторую кладёшь в план и возвращаешься к ней в ближайшей логической точке.**
  - 🔒 **Всегда, когда у тебя что-то не получается по вине кода, — баг сразу в бэклог (правило пользователя 2 нояб.).**
- 🔒 **Никогда не оставляй задачи открытыми и не уходи вперёд. Не можешь закрыть — редизайн, меняй подход.** Вопрос пользователю — с закрывающим вариантом: пункт не стоит «в ожидании ответа».
- 🔒 **Просто. Не строй защиту от редких сбоев.** Если что-то сломается, агент заметит это по журналу и починит.
  - 🔒 **Простота кода, дизайна и архитектуры — фундаментальный принцип. Надёжность — из модульности и чистоты, а не из защит.**
  - 🔒 **Восстанавливаем только основные ожидаемые ветки флоу. Всё остальное — чистый перезапуск компонента или процесса; крайние случаи не закрываем и не тестируем.**
  - 🔒 **«Система ловит, агент чинит» — для любого дизайна любого модуля и системы. Это защищает систему от переусложнения.** Код системы только обнаруживает ошибку и не пускает её дальше: останавливает, отказывает, пишет в журнал с причиной. В систему не встраиваются самопочинка, автоподбор, обходные пути и запасные режимы. Чистый перезапуск — не самопочинка: причину не угадывает, состояние не правит, начинает с хранилища.
  - 🔒 **Не ставь арбитрарных целей вроде «200 МБ/час». Отталкивайся от простоты решения, не усложняй. Сначала замеры и полезность, тюнинг потом.**
    - 🔒 **Не вводи рандомных ограничений — например, мегабайт в час на каждый поток.**
  - 🔒 **Не придумывай своих странных механизмов. Задавай вопросы вместо этого.**
  - 🔒 **Обратная совместимость не нужна. Миграции делают агенты. Никогда не делать кодовых миграций или обратной совместимости, если это не попрошено явно (правило пользователя 4 нояб.).**
  - 🔒 **Пользователь задал вопрос — сначала ответ на него и на прежние вопросы без ответа, потом работа (правило пользователя 23 окт.).**

  - 🔒 **Если что-то устарело — удалять, а не отмечать как устаревшее.** Касается правил, памяти, документов и кода.
- 🔒 **Язык: общение по-русски, идентификаторы по-английски, комментарии в коде по-русски.** В документах человеческие имена вместо кодов вроде A2/R146.

## Проверка

- 🔒 **Изменение с доказательством: команда, результат и одно число до и после.**
  - 🔒 **✓ — только после проверки, а не до: строка «Готово» прогнана числом, второй проход сделан.**
  - 🔒 **Проверка — один раз и по изменённому. Перед запуском называешь, что она проверяет в этом изменении; не можешь назвать — не запускаешь.**
  - 🔒 **Проверка, которая не может упасть, проверкой не считается и в числа не идёт.**
  - 🔒 **Тесты мутаций не запускаешь — только по запросу пользователя (правило пользователя 6 нояб.).**
  - 🔒 **Изменение только во фронте (`web/`) — гоняешь тесты фронта и снимки тронутых экранов настоящего кода в браузере, жесты — мышью и пальцем; все бэкенд-тесты бежать не обязательно (правило пользователя 3 нояб.).**
  - 🔒 **Критик работает только по живому прототипу, снимки — не вход (правило пользователя 6 нояб.).** Живого нет — сначала поднять, потом критик.
    - 🔒 **Критик в прототипе фокусируется не на мелочах, а на сути — опыт, структура (правило пользователя 6 нояб.).**
    - 🔒 **Если работает Fable, критик UI не нужен — только по просьбе пользователя (правило пользователя 10 нояб.).**
    - 🔒 **Критика не гоняешь по кругу: максимум 1 раз на дизайн, если пользователь не просит больших изменений (правило пользователя 6 нояб.).**
  - 🔒 **Проверка решений — эталоны и тесты на моках.** Стенд Host — поддельные SDK, Relay, Keeper и часы.
  - Эталон проверяет одну часть или один модуль на своём зафиксированном входе и закрепляет свойство, а не слепок прогона. Эталоны закрепляют ожидаемые ветки и graceful shutdown, крайних случаев не закрепляют. Номер эталона — номер теста.
  - 🔒 **Источник свойства эталона — слово пользователя, факт или нынешнее поведение кода с пометкой «чьё: код».** Мнение агента источником не бывает.
    - 🔒 **Эталон с пометкой «чьё: код» архитектор может сменить вслепую при сведении дублей; 🔒 и слово пользователя — нет (правило пользователя 6 нояб.).**
- 🔒 **Улучшение не ломает историю. Стало хуже на эталонах — новая итерация, а не откат.**
- 🔒 **Чиним в своём слое.** Порядок: заморозить → факты → слой, где живёт логика, и нарушенный инвариант → фикс в этом слое → регрессия.
  - 🔒 **У каждого понятия один владелец — реестр «понятие → владелец» с гейтом.** В Host это реестр модулей: у запроса, кадра, поля roster, MCP-сервера, ключа `env` и раздела хранилища — один модуль; двое — Host не стартует.
  - 🔒 **Пункт закрывается устранённой причиной, а не зелёным гейтом.**
  - 🔒 **Гейт проверяет устройство кода, а не текст.**
- 🔒 **У защиты есть метрика пользы и дата пересмотра.** Заменённое удаляется.

## Устройство (решения дизайна)

- 🔒 **Части независимы и пользуются друг другом только через контракт.** Контракт — публичный вход модуля: кадры, запросы, API; владелец — сам модуль. Зависимости модуль объявляет в манифесте. Гейт: импорт мимо контракта или без объявленной зависимости — сборка падает. Часть падает и перезапускается одна, остальные ждут и переподключаются. Веб-приложения внутри — тоже независимые модули по тому же правилу.
  - 🔒 **Модуль живёт в любом репо. В какие приложения он входит, пишет он сам; код идёт через каталог «Выпусков», приложения собирают «Выпуски».**
- 🔒 **Трафик флота не идёт через наш экземпляр, один на весь флот: Worker — без состояния, объект — на зону (машину или сессию), записи — в базе D1 своего модуля, файлы — в R2.** Правило — о нашем коде, а не о хранилище платформы: главная копия базы D1 одна, но она у Cloudflare и нашего кода не исполняет.
  - 🔒 **Служебное отдельно от пользовательского (правило пользователя 3 нояб.).** Служебное — то, чем работает флот; пользовательское — то, что человек настраивает под себя. Они не хранятся вместе и не смешиваются в одном модуле.
- 🔒 **Каждая часть отказоустойчива и останавливается штатно (graceful shutdown).** По сигналу: не принимает новое → доводит или отдаёт текущее → сохраняет своё в хранилище → закрывает соединения с причиной → выходит; не успела — жёсткий выход, это ожидаемая ветка. Остановкой Worker-модулей управляет Cloudflare: их ветка — «соединение оборвалось → клиенты переподключаются».
  - 🔒 **У всех операций должен быть лимит и поддержка graceful shutdown (слово пользователя 2 нояб.).**
- **Ожидаемые ветки восстановления — закрытый список:** процесс claude умер — один resume, второй сбой до готовности — `failed`; часть машины, включая Host, умерла — один перезапуск, второе падение — `failed`, дальше решает агент (`set on:false` → `on:true`); keeper умер или подменил себя — ОС поднимает его, держатели живут, keeper подключается к своим; соединение с объектом relay машины оборвалось — клиенты переподключаются; прямой запрос к Worker'у не прошёл — отказ словом; ошибка модуля — модуль выключен, в roster `failed`. Чего в нём нет — остановить, журнал, чистый перезапуск.
- **Только документированные интерфейсы Claude Code.** Сессиями управляет Claude Agent SDK; версия SDK закреплена точно, в окружении сессий `DISABLE_UPDATES=1`. Свой протокол stdin не пишем.
  - Исключения — как в claude-fleet (слово пользователя 31 окт.): управление аккаунтами — вход по ссылке и коду с пульта, своя папка входа на аккаунт, опрос входа и лимитов, токен не используем («мы будем использовать такой же подход к аккаунт-менеджменту»); Remote Control — метод SDK `enableRemoteControl` и снятие привязки `bridge-session` в файле разговора; переписка Claude Code между сессиями выключена переменной `CLAUDE_CODE_HARBOR_KITE=0` — сессии говорят друг с другом только через fleet, `SendMessage` субагентам остаётся (слово пользователя 1 нояб.: «юзай енв»); методы `query` вне публичных типов SDK, которыми работал fleet: `askSideQuestion`, `getTaskOutput`, `cancelAsyncMessage`, `mcpAuthenticate`, `getStatus`, `getHooksListing` — при обновлении SDK живая проверка, метод пропал — отказ словом (слово пользователя 4 нояб.).
- **Relay не пишет на диск.** Roster — из attachments живых соединений объекта машины. Какие машины есть, знает только gate (`keys.list`).
- **Host — единственная точка к сессиям** (слово пользователя 27 окт.: «не рядом, а через»; «наш контроллер должен стать точкой»). С процессом claude говорит только SDK Host; клиенты получают сообщения SDK и шлют запросы.
- **Host — ядро и модули.** Ядро: сессии, держатели процессов claude, связь с Worker-модулями, реестр модулей. Функция — модуль: папка `host/modules/<имя>/` и строка в списке модулей.
  - Модули пользуются друг другом только через контракт; SDK, держатели и участники рации — только через ядро. Ядро держит соединение с relay каждой машины флота; адреса Worker'ов — в списке сборки; модуль объявляет в `uses`, каким пользуется.
  - Ошибку модуля ловит ядро: модуль выключается в этой сессии, roster показывает `failed`.
  - После перезапуска Host модуль поднимает своё из хранилища.
- **Relay не знает модулей.** Запрос с `callsign` или `machine` пересылает Host как есть; кадр с `to` доставляет по адресу. Новая функция Host — без правки Relay.
- **Keeper без решений.** Процессы claude держит Host через свои держатели; keeper исполняет план, обновление Host — по плану, сессии не останавливает.
- **Режим «разрешено всё»; вопросы человеку — наружу.** Новая сессия идёт в «разрешено всё», остальные режимы включает человек (слово пользователя 4 нояб.). `AskUserQuestion` не решается автоматически: его получает тот, кто дал задачу, и зрители сессии; первый ответ выигрывает.
- **Протокол:** тип кадра — в `type`; у запроса `id`, ответ — `reply {id, ok, result | error}`; ошибки — словами.
- 🔒 **В интерфейсе приложений — только то, что несёт информацию постоянному пользователю: серые поясняющие тексты и лейблы без информации убираются отовсюду (правило пользователя 2 нояб.).**
  - 🔒 **Не пиши лейблы и подписи без долгосрочной ценности — то, что пользователь уже понял однажды (правило пользователя 6 нояб.).**
  - 🔒 **Не делать вложенных и скрытых вещей: форма — одного уровня, поля не прячутся (правило пользователя 10 нояб.).**

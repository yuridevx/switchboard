Память флота

Память ведут сильные модели: читают, пишут, держат индекс в мере и отсекают лишнее. Модели слабее память только читают. Всё стоит на штатной памяти Claude Code; флот добавляет замок записи по модели, наследование, след и справку.

Кто что делает с памятью

добавляет этот дизайнуже работаетотказновое в этой версиинажмите на часть или стрелку
Одна память, два режима. Сильная модель ведёт память проекта и сверяет её с сырьём. Модель слабее получает тот же индекс и те же записи, но запись ей закрыта. Каждое чтение, запись и отказ уходят строкой в историю флота.

Сильной модели память нужна сырой и своей. Выжимка службы ей проигрывает, а память от слабого писателя срезает результат. На флоте модель вне списка ведёт 6 % разговоров и делает каждую пятую запись в общую память.

Читает модель слабее

Старт от модели не зависит. Подсказку, индекс и папку памяти любой модели даёт Claude Code. Флот добавляет одно: отказ до вызова записи, если модель сессии не из списка. Смена модели перезапуска не просит.

Жизнь сессии: Claude Code и флот

добавляет этот дизайнуже работаетвремя идёт слева направо
Память течёт потоками Claude Code. Он кладёт ядро в окно, отдаёт записи по запросу, перечитывает индекс после сжатия и сам требует сократить индекс у предела. Флот встаёт в четыре места: открытие, старт, чтение, запись. Смена модели остаётся как есть.

Ядро и фокус

Индекс каждой памяти против предела Claude Code. Самый большой занят на треть. Фокус держит та, кто пишет: у предела Claude Code возвращает ей требование переписать индекс. Своего отсечения флот не строит, пока след не покажет, что отсекать.

Сырьё как опора

Неверную запись лечит только сверка с тем, что было сказано. Сырьё уже лежит на машинах, а запись несёт номер своего разговора. Справка называет три пути к сырью; нового инструмента нет.

Порядок реализации

  1. Замок по модели. Хозяин кусочков держит список пишущих моделей и на каждом вызове записи в память кусочка сверяет с ним модель из документа сессии: не из списка — отказ с причиной до вызова и строка журнала «отказ». Опции запуска от модели не зависят, смена модели идёт как сейчас. Сессия без кусочка с памятью стартует с выключенной встроенной памятью.

  2. Наследование. Сессия, открытая другой сессией без названных кусочков, получает кусочки родителя: правило «неназванную часть документа ставит её владелец» получает документ родителя. Родитель на другой машине — один запрос его документа из картины флота. Пустой список — без кусочков.
    Готово: новых эталонов 2; эталон «проект родителя» зелёный без правки свойства; на тестовом флоте дочерняя от сессии с кусочком показывает его в картине флота — 1 из 1.
  3. След. Машина пишет ту же строку журнала на каждое чтение записи и каждую запись, уровнем «инфо»: позывной, модель, кусочек, запись, действие.
    Готово: новых эталонов 2; на тестовом флоте после чтения, записи и отказа запрос истории по имени строки отдаёт 3 строки из 3.
  4. Справка. Страница «Память» в справке флота и одна строка о ней в инструкциях сервера: зачем память, три слоя, пути к сырью, правило «пишут сильные модели» без списка моделей. Правил записи нет.

  5. Мера индекса из одного места: машина, которая режет индекс по пределу Claude Code, отдаёт пульту готовую меру.
    Готово: чисел предела в коде пульта 2 → 0; node tools/test/run.mjs host web зелёный; снимок вкладки «Память» настоящего кода.

модуль приложения Claude SDK

chat

Человек пишет сессии Claude Code с пульта или с телефона — только через chat: session.prompt кладёт его текст во ввод без обёртки, которой флот помечает сообщения сессий и скриптов. Host — программа на каждой машине, через которую идут все сессии; chat — его модуль: кладёт сообщение человека с картинками и документами во ввод Claude Agent SDK, отдаёт разговор для экрана чата и подсказывает файлы папки для «@». Живую ленту при этом шлёт соседний модуль watch.

ввод очередь сообщений SDK: модель берёт их на границе шага uuid имя сообщения — одно в ленте, истории и ответе вложение картинка, PDF или текст — блок того же сообщения

Когда модель прочтёт сообщение

Ответ на session.prompt приходит сразу: сообщение в очереди ввода. Прочтёт его модель, когда сможет, — это зависит от того, чем занята сессия.

Вложения — блоки того же сообщения

Текст и вложения одного session.prompt становятся одним сообщением SDK: так claude получает их одним ходом. Тип вложения задаёт блок; блока для типа нет — отказ до ввода.

кадр session.prompt→SDKUserMessage · message.content text: "Что на скрине? Сравни с @src/worker.ts"→{ type: "text", text } screen.png · image/png→{ type: "image", source: { type: "base64", media_type: "image/png", data } } spec.pdf · application/pdf→{ type: "document", source: { type: "base64", media_type: "application/pdf", data } } notes.txt · text/plain→{ type: "document", source: { type: "text", media_type: "text/plain", data } } build.zip · application/zip✕reply ok:false · bad_attachment — во ввод ничего не ушло

Картинки — image/png, image/jpeg, image/gif, image/webp. Файл папки сессии не вкладывают, а упоминают: @src/worker.ts в тексте раскрывает сам claude.

История страницами

Разговор лежит в файле сессии у claude; читает его функция SDK. chat отдаёт последние limit записей до before. Лента watch и история пересекаются — клиент склеивает их по uuid.

Контракт

    
Версия контракта — 1. Запросы адресованы callsign сессии: relay везёт их Host её машины как есть.

{ "type": "session.prompt",
  "id": "p-3", "v": 1,
  "callsign": "site@laptop",
  "uuid": "9c4d…",
  "text": "Почини сборку",
  "attachments": [ { "name": "screen.png",
    "media_type": "image/png",
    "data": "iVBOR…" } ] }
← { "type": "reply", "id": "p-3",
    "ok": true,
    "result": { "uuid": "9c4d…" } }

      
uuid ставит клиент; нет — ставит chat. Пришёл disconnected — клиент ищет этот uuid в истории, прежде чем слать снова.

Эталоны chat

    
Прогоняются на стенде Host: поддельные SDK, relay, keeper и часы. Номер эталона — номер теста.

  

  

    
15

      
Чат шлёт простаивающей site@laptop session.prompt «Почини сборку», затем session.history.

      
Сообщение — во вводе SDK как сообщение человека, без обёртки флота; ход начался; reply ok. История возвращает записи разговора, среди них — это сообщение. В процесс claude пишет только SDK Host.

      
чьё: факт — опыт 17: session.prompt начал ход, session.history вернул 6 записей, с процессом claude говорил только SDK Host.

    
82

      
session.prompt с текстом и вложениями screen.png (image/png) и spec.pdf (application/pdf); затем второй — с build.zip (application/zip).

      
Первый — одно сообщение SDK, content = text, image, document по порядку. Второй — reply ok:false, error: bad_attachment; во ввод ничего не ушло; в журнале — тип вложения.

      
чьё: факт — Agent SDK 0.3.311: картинки и документы идут в message.content сообщения пользователя; устав — «Система ловит, агент чинит»: отказывает и пишет в журнал с причиной.

    
83

      
session.files с query: "worker" в site@laptop; затем session.prompt «Сравни с @src/worker.ts».

      
Файлы — пути от папки сессии: src/worker.ts, test/worker.test.ts. Сообщение уходит во ввод без client_composed — упоминание @src/worker.ts раскрывает сам claude.

      
чьё: факт — Agent SDK 0.3.311: client_composed выключает раскрытие @path; без него claude раскрывает упоминания файлов.

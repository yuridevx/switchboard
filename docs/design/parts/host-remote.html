модуль приложения Claude SDK

remote

Remote Control: каждая сессия Host видна и управляется в claude.ai и в приложении Claude. Модуль включает его у процесса сессии после старта, кладёт ссылку в roster и перед стартом снимает привязку к сессии claude.ai, если сессия поднимается на другом аккаунте, на другой машине или из точки — после отката. Имени не ставит: заголовок в claude.ai — имя сессии.

Remote Control мост процесса claude к claude.ai сессия claude.ai то, что видно в claude.ai и в приложении Claude привязка запись в файле разговора: какая сессия claude.ai и чей аккаунт ссылка адрес сессии claude.ai — кнопка «В Claude» на пульте

Не делаетне ставит имяне пересылает сообщения и ответы — их носит сам claudeне меняет аккаунтне повторяет неудачное включение

Что документировано, а что — нет

Сессия Host — это claude под Agent SDK, то есть процесс в режиме stream-json. Документированные способы включения на такой процесс не действуют; действует только запрос, которого в документации нет.

Документировано

факт: документация Claude Code
  • claude --remote-control (--rc) и /remote-control — у интерактивной сессии.
  • remoteControlAtStartup — настройка «включать в каждой сессии».
  • claude remote-control — отдельный серверный процесс со своими сессиями, не сессии Host.
  • Имя — --name, /rename. Нужна подписка claude.ai и полный вход; CLAUDE_CODE_OAUTH_TOKEN Remote Control не поднимает.

Вне документации

исключение
  • query.enableRemoteControl(true) — управляющий запрос remote_control; метод есть в коде SDK 0.3.311, в его типах нет. Ответ — session_url и bridge_session_id.
  • Запись bridge-session с пустым bridgeSessionId в файл разговора — так claude сам снимает привязку. Место файла документировано, формат — нет.
  • Новая версия SDK может сломать оба места — эталоны 230–236 и 239 ловят это до выпуска.

Что происходит — по случаям

Четыре дорожки: модуль, процесс claude, файл разговора и claude.ai. Выберите случай; внизу — что увидит человек в claude.ai.

Когда снимать привязку

claude сверяет владельца привязки с аккаунтом, под которым поднимается. Не совпало — он заводит новую сессию claude.ai без истории и имени и навсегда запрещает разговору историю в claude.ai. Поэтому решение — до старта процесса, пока claude не прочёл файл. Разговор из точки — снимать всегда: привязка в нём ведёт в сессию claude.ai, где есть сообщения после точки. Так делает claude-fleet (слово пользователя 31 окт.).

Что даёт каждая ветка в claude.ai

attach
мост жил в процессе всё время — та же сессия; писать в файл живого процесса нельзя: claude держит привязку в памяти и допишет её поверх
нет файла
новая сессия — новая сессия claude.ai с её именем
из точки
новая сессия claude.ai — с историей до точки и именем; прежняя, с сообщениями после точки, остаётся в claude.ai без процесса
тот же
та же сессия claude.ai, история на месте
другой
новая сессия claude.ai у нового аккаунта — с историей и именем
записи нет
сессия пришла с другой машины, из копии или хранилище Host потеряно — снять: кто заводил прежнюю привязку, неизвестно

Аккаунт сессии знает slots: модуль спрашивает его machine.slots и сравнивает со своим account — тем, под которым включал мост. Другого места у этого значения нет. Вид старта знает ядро: s.info.start — point, когда сессию поднимают по разговору, положенному из точки.

Подмена в слоте не рвёт Remote Control

Проба 27 окт.: файл входа в слоте заменили, процесс не трогали. Мост остался у прежнего аккаунта и работал; новая сессия claude.ai понадобилась только после перезапуска. Поэтому модуль на подмену не реагирует — он смотрит на аккаунт в миг старта.

Что из этого следует

  • Пока процесс жив — ничего не делать: сессия claude.ai у infirex отвечает, ссылка в roster верна для infirex.
  • y0902 её не видит — 404 по ссылке. Человек, вошедший в claude.ai как y0902, увидит сессию после ближайшего перезапуска.
  • Почту claude не меняет — и после подмены называет себя infirex. Поэтому аккаунт модуль берёт у slots, а не у claude.
  • Перезапуск — по правилу выше: в слоте y0902 ≠ infirex → снять → новая сессия claude.ai с историей.

Подробно о подмене — slots.

Имя и всё, что приходит из claude.ai

claude берёт заголовок сессии claude.ai по порядку — первое, что есть. Модуль включает мост без имени, и заголовок — имя сессии. А всё, что человек делает в claude.ai, claude сам кладёт в поток сессии; там это видят модули-владельцы.

Эталоны remote

Стенд Host: поддельные SDK, relay, keeper и часы. Поддельный query отвечает на enableRemoteControl, поддельный slots — на machine.slots; файл разговора — во временной папке. Номер эталона — номер теста.

приложение Claude SDK · модуль Host

fleet

Переписка сессий Claude Code по позывным. Каждая сессия флота получает позывной вида site@laptop и три инструмента: кто на связи, написать, ответить на вопрос другой сессии. Сообщение ложится во ввод сессии-адресата: простаивающая просыпается, занятая читает его на ближайшей границе шага — после текущей команды, не прерывая её. Адресата нет на связи — отказ сразу, без очереди.

callsign позывной сессии: имя@машина ход от ввода до сообщения SDK result граница шага инструмент закончил, модель ещё не вызвана снова relay сервер флота в Cloudflare: везёт кадры по адресу

Инструменты и запрос

    
Три инструмента для модели и один запрос для всех остальных. Ошибки — словами; подробность — строкой в журнале того, кто отказал.

  

  

    

      
fleet.list
инструмент MCP

      
Кто на связи: сессии флота и клиенты. Выжимка последнего roster, который fleet получил от relay через ядро.

      
mcp__fleet__list({})
→ { "me": "site@laptop",
    "sessions": [
      { "callsign": "poe-bot@pc", "state": "busy" },
      { "callsign": "profiles@laptop", "state": "idle" } ],
    "clients": [ "phone", "panel-desk" ] }

      
отказ: disconnected нет связи с relay — roster мог устареть

    

    

      
fleet.send
инструмент MCP

      
Написать сессии или клиенту. Ответа адресата не ждёт: тот ответит своим fleet.send.

      
mcp__fleet__send({ "to": "poe-bot@pc",
  "text": "Станция собрана. Прогони эталоны?" })
→ "доставлено: poe-bot@pc"

mcp__fleet__send({ "to": "phone", "text": "Готово" })
→ "отправлено: phone"   // клиенту — без подтверждения

      
отказ: offline disconnected shutting_down — результат инструмента с isError

    

    

      
fleet.answer
инструмент MCP

      
Ответ на вопрос другой сессии, которой эта дала задачу. Вопрос приходит во ввод тегом <fleet-question>; дальше — запрос answer модуля questions.

      
mcp__fleet__answer({ "to": "profiles@laptop",
  "question": "toolu_01Hq…",
  "answers": {
    "Какую базу мигрировать первой?": "стенд" } })
→ "принято"

      
отказ: already_answered unknown_question offline disconnected

    

    

      
message
запрос · v 1

      
Путь сессий и скриптов. С wait: true ответ приходит после конца хода, который взял сообщение. Человек с пульта или телефона пишет сессии запросом session.prompt модуля chat — без обёртки: у текста человека один путь во ввод.

      
→ { "type": "message", "id": "m-12", "v": 1,
    "to": "profiles@laptop",
    "text": "Сведи память профилей",
    "wait": true }
← { "type": "reply", "id": "m-12", "ok": true,
    "result": { "text": "Свёл: 3 файла, конфликтов нет." } }

      
ok во вводе · отказ: offline disconnected shutting_down contract_mismatch turn_failed — ход с сообщением кончился ошибкой или оборвался

    

  

  

    

      
что видит модель адресата

      
<fleet-message from="site@laptop">
Станция собрана. Прогони эталоны?
</fleet-message>

      
Отправитель — в тексте: поле origin модель не видит (опыт 12). from ставит relay или ядро Host отправителя — модель адресата верит только ему.

    

    

      
что fleet кладёт во ввод SDK

      
{ type: "user", parent_tool_use_id: null,
  priority: "next",
  origin: { kind: "peer", from: "site@laptop",
            name: "site@laptop" },
  uuid: "9b1e…",          // для wait
  message: { role: "user",
    content: "<fleet-message from=…>…" } }

      
Клиенту (to: "phone") — кадр message без id и запрос модулю push этой машины: host.request("notify", { v: 1, clients: ["phone"], frame: { type: "message", from, notify: { title, body, tag } } }). Кого нет на связи, push решает по roster.

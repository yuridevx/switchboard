Worker-модуль

github

Приложение GitHub флота. github держит ключ приложения и по запросу выдаёт участнику рации короткий токен установки: на час и на один репозиторий. С этим токеном машина делает git pull и push, не держа своего ключа к GitHub. Первый потребитель — модуль Host profiles: память профилей. Другие возможности приложения GitHub добавляются новыми запросами сюда же. Участник рации с адресом github, со своим хранилищем — Durable Object. Адреса в интернете у него нет: приложение создаётся с пульта.

Каналы github

    
С relay — по двум привязкам, как у любого Worker-участника. Наружу — только к API GitHub. Байты git идут мимо github: машина ходит в GitHub сама, с токеном из ответа. Нажмите номер.

  

  

    
    

  







  

    
По шагам

    
Настройка — один раз на флот, с пульта: GitHub создаёт приложение по manifest и возвращает браузер на адрес пульта с одноразовым кодом; github меняет код на ключ приложения. Дальше машина берёт токен перед каждым сетевым git. Что github помнит

    
Одна запись — приложение. Её кладёт github.setup, и только github её читает: в ответы, кадры и журнал ключи не попадают. В Workers secrets ничего нет: ключ появляется при настройке, человек его не видит и не переносит.

  "at": 1793457720000, "by": "panel" }

      
Токенов, установок и списка репозиториев github не хранит: токен живёт час у того, кто его взял, а установки и репозитории github спрашивает у GitHub на каждый запрос. Второго места для того, что знает GitHub, нет.

      
client_secret и webhook_secret из ответа GitHub не сохраняются: входа через GitHub и вебхуков у флота нет. Понадобятся — их выпускают заново в настройках приложения на GitHub.

Сбои и остановка

    
Всё, что github знает, лежит в хранилище объекта и переживает любой перезапуск. Остановкой управляет Cloudflare: для машины это offline на один запрос; синхронизация профилей повторит его в свой следующий раз.

Эталоны github

    
Каждый проверяет github на своём входе: relay и GitHub — поддельные, часы заданы. Номер эталона — номер теста.

  

  

    
240

      
Приложение есть: id: 1047113. От @laptop — github.token { repo: "team/profiles" }. Поддельный GitHub: установка 58203311.

      
Поддельный GitHub получил GET /repos/team/profiles/installation с JWT, где iss: "1047113", затем POST /app/installations/58203311/access_tokens с repositories: ["profiles"], permissions: { contents: "write" }. Ответ — ok с token и expires_at ровно из ответа GitHub. Хранилище не изменилось.

      
чьё: код claude-fleet — POST /api/github/token {repo} → {token, expires_at}, токен установки по JWT приложения; факт — документация GitHub: токен установки ограничивается repositories и permissions и живёт час.

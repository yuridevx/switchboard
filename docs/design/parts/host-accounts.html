модуль приложения Claude SDK

accounts

Аккаунты Claude на машине. Host — программа на каждой машине, через которую идут все сессии Claude Code; accounts — его модуль. С пульта или телефона он впускает ещё один аккаунт по ссылке и коду, проверяет вход, знает почту, тариф и лимиты, удаляет аккаунт. У каждого аккаунта своя папка Claude, поэтому вход, почта и опрос лимитов не смешиваются через общие настройки машины. Аккаунт живёт ровно в одном месте: в своей папке или в слоте.

аккаунт имя на машине: y0902, corp папка аккаунта своя папка Claude: почта, тариф, вход вход файл, который claude перечитывает перед вызовом модели слот папка входа, в которой работают сессии окно five_hour, seven_day: доля и час сброса

Где аккаунт работает и как меняется у живых сессий — slots; профиль сессии — profiles.

Своя папка — и вход в одном месте

Всё, что accounts делает с аккаунтом, — вход, проверка, опрос лимитов — идёт короткими процессами claude с папкой этого аккаунта. Папка Claude машины — вход вашего Claude Code в терминале и редакторе — не трогается.

Общая папка Claude машины
  • вход аккаунта переписывает почту всей машины — и у вашего Claude Code
  • опрос лимитов y0902 отвечает по профилю, записанному последним: в claude-fleet так приходили лимиты чужого аккаунта (живое 30 окт.)
Своя папка у каждого аккаунта
  • почта, тариф и вход — в папке аккаунта, его спрашивают своей папкой
  • папка — по документации Claude Code: CLAUDE_CONFIG_DIR, «своя папка — свои настройки и вход claude.ai»

Войти ещё аккаунтом

    
С пульта или телефона, без терминала на машине. Ссылку даёт claude, код со страницы входа уходит запросом по TLS через relay — шифрования поверх TLS в первом выпуске нет. Пройдите по шагам или нажмите строку схемы.

  

  

    

    

      
      

      
      

      

        
        
        
      

    

  

  

    
    
      
  • Методы входа claudeAuthenticate и claudeOAuthCallback есть в коде Agent SDK 0.3.311, в его типах — нет. Вход — исключение из «только документированные интерфейсы»: управление аккаунтами как в claude-fleet, решение пользователя 31 окт.
    • 
      
  • Токен не годится. claude setup-token даёт токен только для запросов к модели, а Remote Control требует полный вход — поэтому вход по ссылке и коду.
    • 
      
  • Код — секрет. Он только в теле machine.login_code: по TLS от браузера до relay и от relay до Host; relay держит его в памяти и не пишет на диск. Не в аргументах процессов и не в журнале.
    • 
      
  • Повтор. Второй machine.login того же аккаунта закрывает первый процесс входа. Брошенный вход живёт до него или до перезапуска Host.
    • 
      
  • Вход ложится туда, где живёт аккаунт: новый — в его папку; аккаунт в слоте, у которого вход пропал, — сразу в слот.

    account.usage
    
      
    { "type": "account.usage", "id": "u-2",
  "v": 1, "machine": "laptop",

  "at": 1793458680, "windows": {
    "seven_day": { "utilization": 0.66,
      "resetsAt": 1793869200 } } }
← { "ok": true }
    
      
    Наблюдение за окнами аккаунта. Шлёт slots — с каждым событием лимита в слоте, src: "event" — и пульт: расход того же аккаунта на другой машине, по почте, src — имя той машины. Свой опрос accounts пишет с src: "poll". Пульт пересылает дальше только наблюдения самой машины — src: "event" или "poll"; наблюдение с именем машины в src дальше не идёт, и две вкладки не гоняют одно окно по кругу.

Удаляется только своя папка аккаунта.
    
    
    
  
    
  
    
    
    
      слова ошибок
      no_account — такого аккаунта на машине нет
      not_started — machine.login_code без идущего входа этого аккаунта: Host перезапускался или вход начат заново
      bad_code — claude не принял код; процесс входа закрыт, вход — заново
      not_logged_in — account.place аккаунта, у которого нет входа
      in_slot — вход аккаунта отдан в другую папку: класть его ещё куда-то и удалять нельзя

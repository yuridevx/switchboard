модуль приложения Claude SDK

machine

Отвечает на вопросы о самой машине, а не о сессиях: какие на ней папки — чтобы выбрать или создать папку новой сессии, — и что на ней стоит: версии, система, процессы claude. Событий Claude не слушает и сессий не трогает.

Контекст в одну строку. На каждой машине работает Host — программа на Node с Claude Agent SDK, через которую идут все сессии Claude Code этой машины; клиенты (пульт, телефон, скрипты) шлют ему запросы через relay с полем machine, а процессы claude держит служба keeper.

Открыть сессию в папке

Так выбор папки выглядит у клиента. Нажимайте папки или введите путь: каждый шаг — запрос machine.dirs и ответ Host машины pc. Последняя кнопка шлёт session.open — его исполняет другой модуль, manage.

    Запросы к машине — у каждого свой владелец
    
    
    Всё, что пришло с полем machine, relay везёт Host этой машины как есть. Внутри Host ядро находит владельца имени. Общая приставка machine. не значит общего модуля.
    
  
    
  
    
    
    
    
      
    Кто за что отвечает
    
      
      
        
    • machineпапки и состояние машины — этот модуль
      • 
        
    • accountsаккаунты Claude: вход, почта, лимиты
      • 
        
    • slotsслоты и горячая подмена аккаунта
      • 
        
    • profilesпрофили сессий и их память
      • 
        
    • upgradeновая версия Host
      • 
        
    • journalжурнал машины
      • 
        
    • manageоткрыть сессию: папка из machine.dirs или machine.mkdir → session.open
      • 
      
    
      
    Модули не знают друг друга: machine не открывает сессий и не читает журнал, manage не листает папки. Клиент сам складывает шаги.
    
    
    
  
    

    



    
  
    
    
    Состояние машины

    Остановка и сбои
    
      
      
        
    • stop()сохранять нечего, таймеров нет; начатое чтение папки доходит до reply
      • 
        
    • Ошибка в обработчикееё ловит ядро: запрос получает module_error, строка stop в журнале; модуль без сессии выключается в этом Host до перезапуска
      • 
        
    • Отказ по путислово в ответе, строка refuse в журнале с путём — чинит тот, кто прислал
      • 
      
    
      
    Ничего не повторяет и не подбирает: опечатка в пути — отказ, а не «ближайшая похожая папка».
    
    
    
  
    

    



    
  
    
    
    Эталоны machine
    
    
    На стенде Host: поддельные relay, keeper и папки. Номер эталона — номер теста.
    
  
    
  
    
    
    90
    
      
    panel-desk шлёт machine.dirs с machine: "pc" и path: "~/Projects". В папке — poe2, site, switchboard, wiki и файлы README.md, todo.txt.
    
      
    Кадр получил только Host машины pc, без изменений. reply ok с { path: "~/Projects", dirs: ["poe2", "site", "switchboard", "wiki"] }; файлов в ответе нет; ни одна сессия и ни один процесс claude не тронуты.
    
      
    чьё: устав — «Запрос с callsign или machine пересылает Host как есть»; «ответ — reply {id, ok, result | error}». Что в ответе — код claude-fleet: «machine.dirs — выбор папки новой сессии, подпапки на своей машине».
    
    
    91
    
      
    machine.dirs с path: "~/Projets" — опечатка; затем с path: "Projects" — не от ~.
    
      
    Первый — reply ok:false, error: not_found; второй — bad_frame. В журнале Host — две строки refuse со словом и путём. Ни одной папки не создано, другого пути не подобрано.
    
      
    чьё: устав — «Система ловит, агент чинит»: код системы останавливает, отказывает, пишет в журнал с причиной; в систему не встраиваются автоподбор и обходные пути; «ошибки — словами».

    Первый — папка создана, reply ok. Второй — exists. Третий — not_found, ни одной папки не создано. Ни одна сессия не открыта.
    
      
    чьё: код claude-fleet — пульт создавал папку новой сессии; устав — «в систему не встраиваются самопочинка, автоподбор, обходные пути».

приложение для ОС

keeper

Служба ОС на каждой машине, без логики. Она держит процессы claude, по одному на сессию, и их ввод-вывод, а ещё запускает Host. Host — программа на Node с Claude Agent SDK, которая ведёт все сессии машины. Пока процесс живёт у keeper, Host можно обновить или уронить посреди хода: новый Host подключается к тому же процессу, и ход доходит до конца.

Host ведёт сессии машины через SDK claude процесс одной сессии канал управления один на Host канал процесса один на каждый claude ключ keeper новый на каждый старт, только в памяти ready Host этой версии готов: после старта или после перезагрузки модулей

Не делает:не разбирает stream-jsonне знает relay, сессий и аккаунтовне решает, что запускатьне перезапускает claudeне откатывает версии

Процесс claude живёт, пока кто-то держит его ввод и читает вывод. Три способа и что с ними бывает, когда Host умирает посреди долгой команды.

API: соединение управления и соединения процессов

    
Host подключается к keeper по TCP на 127.0.0.1: одно соединение управления и по одному на каждый процесс claude. Первая строка каждого — ключ, версия протокола и действие; дальше — строки JSON или сырые байты.

    Слова отказа keeper
    ответ — { "op": "reply", "ok": false, "error": слово }; подробность — строкой в журнале keeper
    
    
    
      
    bad_key
    первая строка без ключа или с чужим — соединение закрыто, ничего не запущено
    
      
    contract_mismatch
    proto не из списка keeper — закрыто, обе версии в журнале; подбора версии нет
    
      
    unknown_op
    незнакомое действие — отказ; первая строка — ещё и закрыто
    
      
    unknown_id
    attach или kill к процессу, которого у keeper нет
    
      
    in_use
    второе соединение управления; attach к процессу, у которого уже есть Host; spawn с id живого процесса
    
      
    spawn_failed
    процесс не запустился — причина ОС в журнале
    
      
    unknown_version
    upgrade к версии, папки которой нет — старый Host не тронут

          Служба ОС и сироты
          
    
          Один исполняемый файл на Go, служба под пользователем. Умирает keeper — с ним всё дерево: Host, процессы claude и их потомки.
          
  
          
  
          
    
          
      
          Windows
          
      
          
        
          запуск
          служба Windows под учётной записью пользователя: стартует с системой, без входа (слово пользователя 31 окт.); пароль Windows установщик берёт один раз, через stdin, и отдаёт диспетчеру служб
          
        
          упал
          восстановление службы — запустить снова
          
        
          сирот нет
          у каждого процесса — своё задание с KILL_ON_JOB_CLOSE; keeper умер — ОС закрывает задания
          
        
          force
          TerminateJobObject — процесс и потомки
          
      
          
    
          
    
          
      
          Linux
          
      
          
        
          запуск
          systemd --user и linger: стартует без входа
          
        
          упал
          Restart=always
          
        
          сирот нет
          systemd завершает всю cgroup службы; у claude ещё PDEATHSIG
          
        
          force
          своя группа процессов — SIGKILL группе
          
      
          
    
          
    
          
      
          macOS
          
      
          
        
          запуск
          не в первой сборке: мака во флоте нет (слово пользователя 31 окт.)
          
        
          почему
          PDEATHSIG нет; как не оставить сирот, проверяет отдельный опыт, когда в флоте появится такая машина

модуль приложения Claude SDK

manage

Сессии по запросу: открыть в нужной папке и аккаунте, сменить модель и усилие на ходу, прервать, откатить файлы, остановить и поднять снова. Host — программа на каждой машине, через которую идут все сессии Claude Code; manage — его модуль, и всё это он делает только методами Claude Agent SDK. Свой ввод в процесс claude не пишет.

спецификация что выбрал клиент: модель, усилие, флаги ответа. Папку держит ядро, слот — slots, профиль — profiles сразу метод SDK, со следующего вызова модели между ходами close() и resume после конца хода

Жизнь сессии

Пять состояний и запросы, которые их меняют. Выберите запрос — на схеме загорится путь, справа шаги: кто что делает.

    Как собирается сессия
    
    
    На session.open ядро Host зовёт query() один раз, из частей всех модулей. У каждого ключа — один владелец: два владельца — Host не стартует. Нажмите модуль — подсветятся его строки.
    
  
    
  
    
    
    
      
    
        
        
        
        
        
        
        
        
      
    
      
    
    
    
    
    append ядро склеивает из частей модулей; у ключа settings и env, у имени в mcpServers — по одному владельцу. Клиент частей query() не задаёт: модель и усилие — поля manage, добавку к промпту, настройки и хуки даёт профиль, папку входа — слот.

    С чем manage работает
    
    
    Поток сообщений manage не читает: готовность сессии и конец хода ждёт ядро. manage зовёт методы и правит свою спецификацию; чужое — папку, слот, профиль, заголовок — не копирует.

      слова ошибок
      unknown_method — метода нет в списке открытых; не вызван
      name_taken — на машине уже есть сессия с этим именем
      bad_spec — нет папки или у поля значение не того вида; что именно — в журнале Host. Незнакомое поле не ошибка — его пропускают
      open_failed — процесс не дошёл до system/init; причина — в журнале, повтора нет
      stopped — session.call к остановленной сессии
    
    
  
    

    



    
  
    
    
    Эталоны manage
    
    
    Прогоняются на стенде Host: поддельные SDK, relay, keeper и часы. Номер эталона — номер теста.
    
  
    
  
    
    
    84
    
      
    Клиент шлёт site@laptop session.call с method: "getContextUsage", затем с method: "close".
    
      
    Первый — reply ok с ответом метода SDK как есть. Второй — reply ok:false, error: unknown_method; close() не вызван, процесс claude жив, сессия работает.
    
      
    чьё: факт — опыт 17: getContextUsage через Host вернул разбор контекста, close — отказ «нет такой операции».
    
    
    85
    
      
    site@laptop посреди хода на opus. session.update с model: "sonnet", effort: "medium". Потом процесс claude умирает, ядро поднимает сессию по resume.
    
      
    Сразу вызваны setModel("sonnet") и applyFlagSettings({ effortLevel: "medium" }); ответ now: ["model", "effort"]; ход не прерван. После resume query() собран с model: "sonnet", effort: "medium".
    
      
    чьё: факт — Agent SDK 0.3.311: setModel меняет модель следующих ответов, applyFlagSettings — это параметр settings query(), применённый посреди сессии; опыт 14 — после смерти процесса разговор цел по resume.

    чьё: слово пользователя 30 окт. — «приложение отказоустойчиво и имеет graceful shutdown»; факт — опыт 14: по resume разговор цел.

модуль приложения Claude SDK

watch

Живая лента сессии для тех, кто её открыл. Host — программа на каждой машине, через которую идут все сессии Claude Code; watch — его модуль: пока сессию смотрят пульт или телефон, он пересылает им каждое сообщение Claude Agent SDK как есть, пачками раз в 100 мс. Никто не смотрит — ничего не шлёт и не копит.

зритель клиент, приславший session.watch: panel-desk, phone пачка сообщения SDK за 100 мс одним кадром seq номер пачки в сессии — по нему видно разрыв

Один ход сессии — двенадцать кадров

Сверху — сообщения SDK за один ход: текст печатается, модель зовёт Bash, команда идёт, ответ дописан. Первое сообщение открывает окно 100 мс, всё, что попало в окно, уходит одним кадром. Включите и выключите зрителей; нажмите кадр — увидите его содержимое.

Кто смотрит и что бывает со связью

Эталоны watch

    
Прогоняются на стенде Host: поддельные SDK, relay, keeper и часы. Номер эталона — номер теста.

  

  

    
14

      
panel-desk шлёт session.watch для site@laptop; идёт ход; через минуту — session.unwatch. До watch и после unwatch сессия тоже шлёт сообщения.

      
session.events с to: ["panel-desk"], не чаще раза в 100 мс, в каждом — все сообщения SDK своего окна по порядку. До watch и после unwatch — ни одного кадра; сообщения без зрителей не копятся.

      
чьё: факт — опыт 17: 44 сообщения SDK за два хода ушли к чату 8 кадрами пачками раз в 100 мс; без зрителей сообщения дальше не идут.

    
80

      
site@laptop смотрят panel-desk и phone. relay присылает roster без panel-desk; потом уходит и phone.

      
Следующие пачки — с to: ["phone"]; panel-desk убран из хранилища watch. После ухода phone — ни одного кадра, открытая пачка пропала.

      
чьё: слово пользователя 30 окт. — «рековерить только основные ожидаемые ветки флоу»; ветка «клиент ушёл → roster без него → его зрители» из списка ожидаемых веток.

    
81

      
panel-desk смотрит site@laptop, последний кадр — seq: 7. Host убит посреди хода; keeper запускает новый, тот делает attach к тому же процессу.

      
Новый Host шлёт panel-desk session.events без нового session.watch; seq снова с 1; сообщения хода, пришедшие после attach, — в пачках по порядку.

      
чьё: слово пользователя 30 окт. — «приложение отказоустойчиво»; факт — опыт 15: новый Host после attach получает тот же ход до конца.

    
110

      
site@laptop смотрели panel-desk и phone; phone прислал session.unwatch. В ходе site — AskUserQuestion: модуль questions зовёт host.request("session.watchers", { v: 1, callsign: "site@laptop" }). Потом relay присылает roster без panel-desk, и questions зовёт ещё раз.

      
Первый ответ — ok: true, result: ["panel-desk"]; второй — ok: true, result: []: зрителей нет — пустой список, не ошибка.

      
чьё: устав, раздел «Устройство» — «AskUserQuestion … получает тот, кто дал задачу, и зрители сессии»; зрителей вопроса questions берёт из этого ответа.

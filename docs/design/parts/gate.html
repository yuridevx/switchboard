Worker-модуль

gate

Проверка ключей флота. Worker без адреса в интернете: его зовёт только relay, по привязке, один раз на каждое новое соединение и на каждом старте объекта флота — про ключи открытых соединений. Ответ — кто это: роль, имя и номер ключа. Секрет флота и список отозванных ключей есть только у gate. Ключи выдаёт его инструмент switchboard invite.

ключ role.name.kid.sig — одна строка kid короткий случайный номер ключа FLEET_SECRET секрет флота: им подписаны все ключи REVOKED номера отозванных ключей привязка Service Binding: вызов Worker внутри Cloudflare

API: verify(key) и revoked(ids)

Два метода на входе Gate. Отказ — значением со словом; исключение значит «gate не ответил», и relay закрывает hello своим словом.

verify(key: string) → { role, name, kid } | { error: "bad_key" | "revoked" }
{ role, name, kid }ключ наш и не отозван — relay пишет карточку
bad_keyне того вида или подпись не сошлась
revokedномер в списке отозванных
исключениеrelay закрывает hello: gate_unavailable
revoked(ids: string[]) → string[]
[ ]ни один номер не отозван — соединения живут
[ "client.phone.k2a9" ]эти номера в REVOKED — relay закрывает их соединения: revoked
исключениесоединения живут, строка в журнале relay; проверит следующий старт

relay зовёт на каждом старте объекта флота — выгрузка и пробуждение, выпуск, чистый перезапуск — с номерами role.name.kid всех открытых соединений. Подписи не нужны: ключи этих соединений уже проверены на hello.

шаги gate

    Где живёт: без адреса

    У gate нет ни адреса workers.dev, ни Version URLs, ни маршрутов. Достучаться можно только по привязке, а привязку к нему объявляет один relay. Привязка в конфиге — и есть доверие: подписей между Worker нет.

    gate · wrangler.jsonc 
    { "name": "switchboard-gate",
  "main": "src/index.ts",
  "workers_dev": false,
  "preview_urls": false,
  "vars": {
    "REVOKED": [ "client.phone.k2a9" ]
  } }

// FLEET_SECRET — секрет Worker:
// <секрет из хранилища> | wrangler secret put FLEET_SECRET
    relay · строка привязки 
    { "binding": "GATE",
  "service": "switchboard-gate",
  "entrypoint": "Gate" }

    Список отозванных — не секрет: номера ключей без подписей бесполезны. Он лежит в настройках gate рядом с кодом. Секрет флота — только в секретах gate и в хранилище владельца.

    только привязкаWorker без публичного адреса достижим только по привязке, которую объявил другой WorkerCloudflare · привязки
    preview_urlsвыключенный workers.dev не выключает Version URLs; включённые — публичныCloudflare · Version URLs
    0 запросоввызов по привязке не оплачивается как запрос; CPU gate оплачиваетсяCloudflare · цены

    Выдача ключа — switchboard invite

    Инструмент gate на машине владельца. Секрет флота читает из stdin, ключ печатает в stdout для следующей команды. В аргументах команды секретов нет. Списка выданных ключей нет нигде. Выберите, кому ключ.

    
    
    
  
    

    



    
  
    
    
    Отзыв ключа
    
    
    Отзыв — один выпуск gate. Новый hello с отозванным ключом отказан сразу, а открытые соединения relay сверяет на каждом старте объекта флота вызовом revoked. Выпуск relay соединений не рвёт. Пройдите по шагам.
    
  
    
  
    
    
    
    
      
    
      
    
      
    
      
    Сменить FLEET_SECRET: новые hello со старыми ключами получают bad_key, invite каждому заново. Открытые соединения живут до своего переподключения — revoked сверяет только номера.
    
    
    
  
    

    



    
  
    
    
    Сбои и остановка
    
    
    Состояния у gate нет: перезапуск ничего не теряет. Остановкой управляет Cloudflare; для того, кто зовёт, это «не ответил» на один вызов. Уже подключённые сбоя gate не замечают.

    Эталоны gate
    
    
    Каждый проверяет gate на зафиксированном входе: секрет флота и список отозванных заданы в тесте. Номер эталона — номер теста.
    
  
    
  
    
    
    111
    
      
    verify("host.laptop.k7f3.<подпись секретом теста>"); REVOKED пуст.
    
      
    { role: "host", name: "laptop", kid: "k7f3" }; gate ничего не записал; в журнале — ok host.laptop.k7f3.
    
      
    чьё: слово пользователя 31 окт. — «разложить на bounded contexts»: проверка ключа — контекст gate.
    
    
    112
    
      
    verify ключа host.laptop.k7f3, подписанного другим секретом.
    
      
    { error: "bad_key" }; в журнале — host.laptop.k7f3 и «подпись не сошлась»; подписи в журнале нет.
    
      
    чьё: устав — «Система ловит, агент чинит»: останавливает, отказывает, пишет в журнал с причиной.
    
    
    113
    
      
    verify верно подписанного client.phone.k2a9…; REVOKED = [ "client.phone.k2a9" ].
    
      
    { error: "revoked" }; ключ client.phone.k8e1… тем же секретом проходит.
    
      
    чьё: устав — «Система ловит, агент чинит».
    
    
    114
    
      
    verify("laptop-key"), затем verify("admin.laptop.k7f3.…").
    
      
    Оба — { error: "bad_key" }, без исключения; HMAC не считался.
    
      
    чьё: устав — «Протокол: … ошибки — словами».
    
    
    115
    
      
    Выпущен gate с workers_dev: false, preview_urls: false и без маршрутов. Запрос из интернета на switchboard-gate.<subdomain>.workers.dev и на Version URL; вызов relay по привязке.
    
      
    Запросы из интернета до кода gate не доходят; вызов relay получает ответ verify.
    
      
    чьё: факт — документация Cloudflare: Worker без публичного адреса достижим только по привязке; Version URLs выключаются отдельно, preview_urls.
    
    
    116
    
      
    Секрет теста в stdin: switchboard invite host laptop.
    
      
    В stdout — одна строка host.laptop.<kid>.<sig>; verify её с тем же секретом даёт { host, laptop, kid }; в аргументах процесса секрета нет.
    
      
    чьё: устав — «Секреты передавать через stdin, никогда через argv».
    
    
    117
    
      
    Телефон client.phone.k8e1 на связи; номер отозван выпуском gate; объект флота стартовал — был выгружен, его разбудил кадр.
    
      
    Соединение телефона закрыто словом revoked, Host и пульт на связи; новый hello с этим ключом — revoked. gate не ответил на проверку при старте — соединения живут, строка в журнале.
    
      
    чьё: факт живого прогона 31 окт. — выпуск relay веб-сокеты не рвёт; устав — «Система ловит, агент чинит».
    
    
    118
    
      
    У gate не задан FLEET_SECRET; Host laptop на связи; телефон шлёт hello.
    
      
    verify бросает исключение с причиной; relay закрывает hello телефона словом gate_unavailable; Host laptop на связи; в журнале gate — «FLEET_SECRET не задан».
    
      
    чьё: устав — «Часть падает и перезапускается одна, остальные ждут и переподключаются».

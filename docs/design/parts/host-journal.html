модуль приложения Claude SDK

journal

Журнал — то, по чему агент замечает и чинит сбои. Система сама ничего не чинит: она останавливает, отказывает и пишет, почему. Каждая часть пишет свой журнал в одном формате; модуль journal добавляет то, что Claude SDK сообщает о сбоях сессий, и отдаёт журнал машины по запросу.

Контекст в одну строку. Части системы: relay — сервис в Cloudflare, через который машины, телефон и пульт обмениваются кадрами; на каждой машине — служба keeper, держащая процессы claude, и Host — программа с Claude Agent SDK, через которую идут все сессии.

Система ловит, агент чинит

Код системы только замечает ошибку и не пускает её дальше. Всё остальное — дело агента, и начинается оно с журнала.

Три вида записи — по уставу

stop

Остановлено. Часть или функция встала: модуль выключен в сессии, Host не прошёл гейт, ход оборван ошибкой API. Агенту — первым делом.

refuse

Отказано. Кадр или запрос отклонён словом: чужой ключ, версия не та, нет такой папки. Чинят того, кто прислал.

note

Событие. Обычный переход: старт, attach, обновление, повтор запроса к API. По ним видно, что было до сбоя.

Одна запись — одна строка JSON

Формат один у всех частей. Слово ошибки — для поиска, причина — для понимания: в ней имена, версии и значения, по-русски.

{ "t": "2026-10-30T14:02:11.204Z",
  "part": "host", "machine": "laptop",
  "who": "core",
  "callsign": "site@laptop",
  "kind": "stop",
  "ev": "module_failed",
  "word": "module_error",
  "why": "budget: on.event(result) — TypeError:
    Cannot read properties of undefined
    (reading 'limit'); модуль выключен
    в сессии",
  "module": "budget" }

В файле — одной строкой; здесь перенесено для чтения.

t
время UTC до миллисекунды; новый файл — каждый день UTC
part
relay, keeper или host
machine
машина; у relay нет
who
кто внутри части: core или имя модуля
callsign
сессия, если запись про неё
kind
stop, refuse или note
ev
что случилось: module_failed, request, hello, host_exit, sdk.result…
word
слово ошибки из контракта — то же, что ушло в reply; у note нет
why
причина словами — обязательна у stop и refuse
…
поля случая: id, type, from, code. Незнакомое поле читатель пропускает

Не пишется: подпись ключа — только его имя и номер; ключ keeper; адрес подписки пушей; текст сообщений сессий — он и так в файле разговора.

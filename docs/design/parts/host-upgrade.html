модуль приложения Claude SDK

upgrade

Ставит на машину новую версию Host из выпусков в хранилище R2: скачивает её, сверяет хэш, проверяет, не пуская в работу. Поменялись только модули — ядро перезагружает их в живом Host. Иначе upgrade просит keeper подменить работающий Host. Если версия Claude Agent SDK та же, сессии не замечают обновления: начатый ход доходит до конца. Если новая — каждая сессия переходит на неё между ходами, разговор сохраняется.

Контекст в одну строку. Host — программа на машине, через которую идут все сессии Claude Code; процессы claude держит служба ОС keeper, поэтому Host можно остановить и запустить заново, не останавливая сессий. Внутри Host лежит SDK закреплённой версии, а внутри SDK — свой бинарник claude.

Откуда берётся выпуск

Слово пользователя 31 окт.: «кто-то деплоит релизы на S3, будь то локальный агент или GH-релиз». Выпуск Host кладут в хранилище Cloudflare R2 — с машины разработчика или из GitHub, одним и тем же инструментом. Машина берёт его оттуда сама, по временному ключу на чтение. Нажмите номер.

Что лежит в R2

switchboard-releases/       бакет выпусков
  host/latest               1.4.1
  host/1.4.1.tgz            выпуск: код ядра и модулей,
                            package.json, package-lock.json
  host/1.4.1.sha256         9f2c41…e07a  1.4.1.tgz
  host/1.4.0.tgz
  host/1.4.0.sha256

Выпуск — один архив на все ОС: ядро и пакеты модулей с их манифестами, без зависимостей. Пакеты модулей лежат внутри выпуска — отдельного «выпуска модуля» нет: модуль приходит новым выпуском Host. latest — последний выложенный; его пишут последним, после архива и хэша. Версия выпускается один раз: есть host/<v>.sha256 — switchboard release отказывает.

Как машина проверяет

  • хэш архиваSHA-256 скачанного архива равен строке из .sha256: архив пришёл целиком и тот самый
  • npm ciхэш каждой зависимости, SDK тоже, — по package-lock.json из архива
  • host --checkверсия в пакете равна запрошенной; гейт ядра: у имени один владелец, всё из uses есть той же версии

Подписи и шифрования нет: в первом выпуске шифрование вырезано целиком (слово пользователя 31 окт.). Писать в бакет могут только выкладчики — по входу wrangler или секрету репозитория; машины только читают, ключом на час.

Чем пользуется

      
    
        
  • host.request("points.creds", { v: 1 })points через relay: временный ключ R2 на чтение бакета выпусков, на час
    • 
        
  • S3 GET · npm ciскачать хэш и архив из R2 по ключу; поставить зависимости по lockfile
    • 
        
  • host.reload(dir)ядро: поставить скачанный выпуск в живом Host. Само сверяет ядро и SDK с работающими, проходит гейт и решает, какие модули перезагрузить; ответ — { from, to, modules, later } и ready keeper, или слово core_changed, check_failed, module_error
    • 
        
  • host --checkядро: гейт новой версии отдельным процессом, без relay, keeper и claude; только после core_changed
    • 
        
  • host.request("upgrade", { v: 1, version })ядро → keeper: остановить Host штатно и запустить эту версию
    • 
        
  • s.info.sdk · host.sdkядро: SDK, которым запущен процесс сессии, и SDK этого Host — у всех сессий свой, значит старую папку можно убрать
    • 
        
  • host.version · host.log(record)ядро: своя версия; шаги и отказы — в журнал машины
    • 
        
  • host.emit({ type: "ledger.add", to: "ledger", ev: "machine.upgraded", … })после ответа keeper на upgrade или ответа host.reload: версия с → на и by — from запроса; в журнал машины эта строка не дублируется
    • 
      

      
uses: { "upgrade@keeper": 1, "ledger.add@ledger": 1, "points.creds@points": 1 } — операция keeper, журнал флота и ключ R2; гейт сверяет операцию с proto keeper. Сессии между ходами при другой версии SDK перезапускает ядро нового Host, не upgrade.

Запрос

    
Версия — точная или "latest": тогда модуль читает host/latest в R2. dryRun: true — только ответить { from, to }: какая версия работает и какая встанет; архив не скачивается, already_current не отвечается — так пульт узнаёт, есть ли новая. Сам модуль ничего не ищет и не обновляется — только по запросу. Ответ: если Host заменяется — до его остановки, пока он на связи; если перезагружаются только модули — после перезагрузки.

Слова отказа

      
    
        
  • bad_frame — нет version или она не вида 1.4.1 и не latest
    • 
        
  • already_current — эта версия уже работает; ничего не скачано
    • 
        
  • upgrade_running — идёт другое обновление этой машины
    • 
        
  • no_release — в R2 нет host/<версия>.sha256; ничего не скачано
    • 
        
  • download_failed — ключ R2 не выдан, скачивание оборвалось, хэш архива не сошёлся или npm ci не прошёл; причина — в журнале; папка убрана
    • 
        
  • check_failed — новая версия не прошла проверку; причина из проверки — в журнале; keeper не тронут
    • 
        
  • module_error — от ядра: новая версия модуля упала в start(); модуль выключен на машине, в roster failed, ready не послан
    • 
        
  • shutting_down — от ядра: Host останавливается; начатое скачивание оборвано, папка убрана

Что проверяется и где отказ

    
До просьбы к keeper работающий Host и сессии не тронуты: любой отказ здесь оставляет машину как была. После неё — только ожидаемые ветки.

  

  

    
    

      
Проверка — отдельным процессом

      
$ node ~/.switchboard/host/1.5.0/host --check
{ "ok": true, "version": "1.5.0",
  "sdk": "0.3.312", "proto": 1 }

$ node ~/.switchboard/host/1.4.2/host --check
{ "ok": false, "version": "1.4.2",
  "why": "session.cost — два владельца:
          cost и dup" }

      
    
        
  • Что делаетсобирает модули и проходит гейт ядра: у имени один владелец, всё из uses есть той же версии; сверяет версию в пакете с запрошенной
    • 
        
  • Когдатолько после core_changed от host.reload: в выпуске другое ядро или SDK, его ставит новый Host через keeper. Выпуск с тем же ядром и SDK проходит тот же гейт внутри host.reload — второй проверки нет
    • 
        
  • Чего не делаетне подключается к relay и keeper, не открывает хранилище, не запускает claude
    • 
        
  • protoканал Host ↔ relay меняется в два выпуска: сначала relay со старой и новой версией, потом Host. Проверка версию только сообщает

Папки версий

    
Каждая версия — своя папка: в ней код Host и SDK с собственным бинарником claude. Процесс сессии запущен из папки того Host, что его запустил, — поэтому папка живёт, пока из неё работает claude.

  

  

    

      ~/.switchboard/host/ — после обновления с той же версией SDK
      
    
        
  • 1.3.9/≈ 300 МБудалена: из неё ничего не запущено
    • 
        
  • 1.4.0/≈ 300 МБзанята: из неё работают claude site, profiles и wiki
    • 
        
  • 1.4.1/≈ 300 МБтекущая — её помнит keeper и запускает при старте
    • 
      

      
Уборка — при старте Host и после каждого перезапуска сессии с другой версией SDK: удаляются папки всех версий, кроме текущей. Сначала — бинарник claude: на Windows ОС не даёт удалить запущенный файл, и папка остаётся целой до следующей уборки. На Linux удаляется сразу, процесс работает дальше.

      
После перезагрузки модулей уборки нет: ядро по-прежнему работает из прежней папки. Она уходит при следующем старте Host — keeper запустит уже новую.

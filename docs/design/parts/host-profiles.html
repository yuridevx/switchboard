модуль приложения Claude SDK

profiles

Профиль сессии — своя папка: CLAUDE.md, profile.yaml и память. Host — программа на каждой машине, через которую идут все сессии Claude Code; profiles — его модуль. Сессия с профилем получает добавку к системному промпту из CLAUDE.md, модель и усилие по умолчанию и свою папку памяти — у каждого профиля свой путь. Профили лежат в git-репозитории; их память profiles сводит между машинами сам, с коротким токеном приложения GitHub флота — от Worker-модуля github.

профиль team/profiles/ops — папка в репозитории CLAUDE.md добавка к системному промпту profile.yaml model, effort, max_effort, fallback_model memory/ память профиля — пишет только claude skills/ скилы профиля — в сессии как ops:<скил> состояние ok · error · conflict

Аккаунт и слот сессии — accounts и slots; открытие сессии — manage; как ядро складывает вклады — ядро.

Из чего собирается запуск

Один query() на сессию ядро собирает из вкладов модулей; у каждого ключа один владелец. Слева — откуда приходит каждая часть, справа — что получилось. Переключайте профиль, слот и модель в запросе.

    У каждого профиля свой путь

    Без своей папки Claude Code держит память по папке проекта. Две сессии в одном проекте с разными профилями писали бы в одну память. Переключите — увидите, куда уходят записи.

    папка профилей на машине 
    ~/.switchboard/profiles/
  team__profiles/   клон team/profiles
    ops/
      CLAUDE.md     добавка к промпту
      profile.yaml  модель и усилие
      memory/       память — пишет claude
    writer/
      CLAUDE.md
      memory/
    profile.yaml 
    model: opus
effort: high
max_effort: xhigh
fallback_model: [sonnet]

    Документация Claude Code, настройка autoMemoryDirectory: «по умолчанию ~/.claude/projects/<папка>/memory/»; в настройках проекта не принимается — profiles отдаёт её в settings запуска.

    Память профилей между машинами

    Раз в минуту, по записи в память и по команде profiles забирает и отправляет память: только папки memory/ и skills/ — каждую своим коммитом, «память» и «скилы», без вопросов человеку, с токеном github на эту синхронизацию. Не вышло — состояние профиля, и модель с этим профилем получает задание свести память. Три случая по шагам.

    
        
    
          
          
          
        
    
      
    
    
    
  
    

    



    
  
    
    
    Доступ к git — токен приложения GitHub
    
    
    Слово пользователя 31 окт.: доступ profiles к git — токен приложения GitHub флота. Своего ключа к GitHub у машины нет: перед каждой синхронизацией profiles просит у github токен на репозиторий, на час, и отдаёт его git через окружение.
    
  
    
  
    
    
    
      
    
    
    
    
      
      
        
    • 1 · github.token { repo }кадр через relay: один на синхронизацию, перед первым сетевым git — clone, pull, push
      • 
        
    • 2 · JWT → access_tokensgithub с ключом приложения просит у GitHub токен: только этот репозиторий, только содержимое
      • 
        
    • 3 · { token, expires_at }токен на час; profiles держит его до конца синхронизации и не хранит
      • 
        
    • 4 · git по HTTPSзаголовок Authorization — переменными окружения git, не в аргументах и не в адресе репозитория
      • 
      
    
      окружение сетевого git
      
    GIT_TERMINAL_PROMPT=0  GCM_INTERACTIVE=never
GIT_CONFIG_COUNT=1
GIT_CONFIG_KEY_0=http.https://github.com/.extraHeader
GIT_CONFIG_VALUE_0=Authorization: basic <base64 x-access-token:токен>
git -c credential.interactive=never pull --no-rebase --no-edit
    
      
    Клон — по адресу https://github.com/team/profiles.git. Отказ github (no_app, not_installed, github_failed) — состояние error с op: "github.token"; git в сеть не идёт. Документация git: GIT_CONFIG_COUNT, GIT_CONFIG_KEY_<n>, GIT_CONFIG_VALUE_<n> добавляют настройку процессу git.

Worker-модуль

ledger

Журнал флота: что случилось с машинами и сессиями, когда и по чьей команде. Участник рации с адресом ledger: модули пишут в него кадром ledger.add, пульт и агенты читают запросом ledger.read, а пропажу и возвращение машин он отмечает сам — по roster от relay. Хранит записи в своём Durable Object с SQLite; резервную копию держит Cloudflare.

запись одна строка: время, что случилось, о ком, кто записал ev что случилось: machine.left, slot.swapped… from кто записал — ставит relay by по чьей команде — со слов пишущего roster кто сейчас на связи — у relay

Одно событие — одно место

Во флоте три места, где остаётся след. Журнал части — сбои, по нему агент чинит. Журнал флота — факты о машинах и сессиях, которые переживают машину или касаются нескольких. Данные модуля — у его владельца, журнал их не копирует. Выберите событие.

  1. 1Сбой или отказ части — в журнал этой части: файл на машине, у Worker — Workers Logs.
  2. 2Факт о машине или сессии, который должен пережить машину или касается двух машин, — в журнал флота.
  3. 3То, что модуль хранит как свои данные, — только у него: точки, лимиты, вход.

Каналы ledger

Адреса в интернете у ledger нет: всё идёт через relay по привязке, как у push. Пишут и читают кадрами рации; хранилище — свой Durable Object. Нажмите номер.

Машина пропала и вернулась — по шагам

    
Свою пропажу машина записать не может, а relay на диск не пишет. Поэтому ledger получает roster, как любое соединение, и сравнивает машины в нём со своими последними записями. Отдельной копии roster он не держит.

Хранение и резервная копия

    
Одна таблица в SQLite своего объекта. Записи не удаляются — то же правило, что у журнала машины: сначала замер, чистка потом и по нему. Резервную копию делает Cloudflare: база объекта восстанавливается на любой миг последних 30 дней.

  

  

    

      таблица
      
CREATE TABLE events (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  t        INTEGER NOT NULL,   -- мс UTC, часы ledger
  ev       TEXT NOT NULL,
  "from"   TEXT NOT NULL,
  by       TEXT,
  machine  TEXT,
  callsign TEXT,
  text     TEXT NOT NULL );
CREATE INDEX events_m ON events(machine, id);
CREATE INDEX events_c ON events(callsign, id);

      
Других таблиц нет: кто был на связи, ledger узнаёт из своих последних machine.left и machine.back.

Восстановление — платформой
факт: Cloudflare

    
// разовый выпуск ledger, когда базу нужно вернуть на миг t
const b = await ctx.storage.getBookmarkForTime(t);   // t — в пределах 30 дней
await ctx.storage.onNextSessionRestoreBookmark(b);   // база вернётся при следующем старте
ctx.abort("restore");                                 // старт — уже с базой на миг t
// затем — обычный выпуск без этих строк

    
Своего запроса восстановления в контракте нет: это редкий ремонт, его делает агент выпуском. Восстанавливается вся база объекта; повторное восстановление на закладку «до» отменяет первое.

Как читают

    
Один запрос — ledger.read. Пульт строит из него экран «Журнал»: по дням, фильтр машины, поиск. Свежие записи он дочитывает на каждом roster, пока экран открыт: нового канала для журнала нет. Попробуйте фильтр.

Сбои и остановка

    
Остановкой управляет Cloudflare. Всё, что ledger знает, — в SQLite; память он не копит, поэтому перезапуск ничего не теряет, кроме кадров, пришедших в этот миг.

приложение Claude SDK · модуль Host

points

Снимает точки сессий своей машины и поднимает сессии из точек. Host — программа на каждой машине, через которую идут все сессии Claude Code; points — его модуль. Точки снимаются только у сессий с пометкой «в R2» — не все сессии нужны в хранилище. Точка — байты файла разговора, файлов рядом с ним и снимка папки git, нарезанные блоками по 1 МиБ, сжатые и положенные в R2 прямо с машины. Подъём собирает файл обратно, кладёт его туда, где его ищет Claude Code, и открывает сессию по resume. Перенос, копия, откат, пожар и смена папки — одна операция. Реестр точек и хозяин сессии — у Worker-модуля points.

точка блоки файлов сессии + строка в реестре подъём собрать файл из точки и открыть сессию по resume пометка «в R2» у сессии снимаются точки; у новой сессии выключена хозяин машина, которой сессия принадлежит; ведёт реестр

Не делаетне разбирает файл разговоране открывает сессии сам — просит manageне решает, чья сессия — спрашивает реестрпривязку к claude.ai не трогает — remoteне шифрует: вход в R2 — только по его ключам

Где points касается Claude и соседей

Модуль сессий: слушает состояние хода, читает файл разговора байтами и поднимает сессию по resume. Нажмите строку — подсветится цепочка.

Решения — у реестра, байты — у машины. Своего у модуля — одна пометка «в R2» в разделе сессии; что лежит в R2 и чья сессия, знает только Worker points.
контракт — три запроса и поле roster
points.save { callsign, stop?, interrupt? } → { point, same } points.raise { machine, sid, point?, copy?, dir, slot?, profile?, name?, files, dryRun? } → { callsign, point, folder, branch } session.r2 { callsign, on } → { point } — поставили, первая точка; { deleted } — сняли, столько точек ушло из R2 поле r2: нет — без пометки; {} — помечена; { error, at } — последняя точка не удалась
слова отказа
not_r2 — у сессии нет пометки «в R2»: точек нет, переносить нечего waiting — сессия ждёт ответа человека, а interrupt не задан running — подъём из точки сессии, которая здесь же идёт: сначала points.save со стопом bad_point — блок не распаковался или длина файла не та bad_dir — папка — другой репозиторий или не репозиторий, а просили правки точки и чужие как есть: not_owner, open_failed, name_taken, offline

Пометка «в R2»

Не все сессии нужны в R2. Точки снимаются только у сессии с пометкой; у новой сессии она выключена. Пометка лежит в одном месте — в разделе этой сессии у модуля points на её машине. Щёлкните переключатель.

    Когда точка
    
    
    Сорок минут одной помеченной «в R2» сессии. Полосы — ходы Claude, кружки — точки. Конец хода — лучший момент: Claude ничего не пишет в файл. Новое в разговоре без хода не появляется, поэтому свободная сессия точек не плодит.
    
  
    
  
    
    
    
    
      
      
      
      Каждый повод ведёт в одну процедуру «снять точку»; неудача — строка в журнале машины и r2: { error, at } в roster, повтор — со следующим поводом. Своих повторов по таймеру нет.
      
    
      
  
      

      



      
  
      
    
      Как снимается разговор
      
    
      Документированных путей перенести сессию на другую машину два: зеркало sessionStore и перенос файла разговора с resume. Снимаем файл: байты, без разбора формата.
      
  
      
  
      
    
      
      
      файл байтами + resume · так снимаем
        
      • документировано: «перенести файл в любую папку ~/.claude/projects/ и вызвать resume»
      • формат не разбираем — меняется между версиями, нас не задевает
      • дописанное уходит блоками; откат файлов manage работает
      • ищется сначала в папке проекта рабочей папки — туда и кладём, прочие копии того же sid — в сторону
      
      
      sessionStore — зеркало в своё хранилище
        
      • SDK отказывает при старте вместе с enableFileCheckpointing — а manage на нём откатывает файлы
      • сессия, поднятая из зеркала, живёт во временной папке настроек; файл на диске удаляется в конце
      • запись в зеркало «как получится»: при сбое пачка пропадает, только mirror_error
      • ключ зеркала — рабочая папка: на другой машине та же папка
      
      
      дописанное кусками + опись
        
      • в R2 уходит ровно дописанное
      • машина помнит, что уже положила: длину, цепочку кусков — второе место рядом с реестром
      • своя сверка «не переписано ли начало» и полная копия раз в сутки
      • блоки по 1 МиБ от начала дают то же без памяти: неизменный блок — то же имя
      
      
      getSessionMessages
        
      • отдаёт сообщения, а не файл: из них сессию не поднять
      • годится для «первых слов» точки — так и используем
      
      
      forkSession
        
      • только на машине, где файл уже есть
      • для копии — опция forkSession при resume собранного файла

      Подъём по шагам
      
    
      Перенос, пожар, откат и копия — один запрос points.raise к машине, где сессия должна встать. Всё это — только у сессий с пометкой «в R2»: у остальных точек нет. Смена папки — копия на ту же машину в новую папку и «Забыть» прежнюю. Поле point в session.open и session.start говорит ядру «старт из точки» — по нему remote снимает привязку к claude.ai, как claude-fleet. Хозяин меняется одной записью — точкой подъёма; до неё всё обратимо одной просьбой к manage. Без пульта — те же запросы с телефона или из скрипта с ключом клиента. Выберите случай и идите по шагам.

      Сбои и остановка
      
    
      Своего у модуля — только пометка «в R2», и она уже в разделе сессии на диске: после перезапуска Host её читает ядро. Неудача точки — строка в журнале машины; следующий повод снимает её заново.
      
  
      
  
      
    
      
      
      
        
      сбойкто поднимаетчто теряется
      
        
          
      Host перезапущен посреди точкиkeeper; на старте — точка каждой помеченной сессииничего: положенные блоки пригодятся
      
          
      R2, relay или points недоступныследующий повод точки; агент — по журналу машиныточка этого повода; снять пометку не вышло — пометка стоит, ответ словом

      старый хозяин вернулсяон сам: not_owner → точка yield → session.remove у себяничего: дописанное — ветка
      
          
      ошибка в коде модуляядро выключает модуль в сессии, в roster — failedточки этой сессии до перезапуска Host

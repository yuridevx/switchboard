points

Реестр точек сессий Claude Code. Точка — сохранённое состояние сессии: файл разговора, файлы рядом с ним и снимок папки git. Из точки любая машина флота поднимает сессию — ту же (перенос, откат) или новую (копия). Точки есть только у сессий с пометкой «в R2»: её ставит человек, у новой сессии она выключена. Байты точек лежат в хранилище Cloudflare R2 сжатыми блоками и идут прямо между машиной и R2; войти в R2 можно только по его ключам доступа. points байтов не видит: он помнит, какие точки есть, чья сессия, сколько хранить, и выдаёт машинам временные ключи R2 — к блокам точек и на чтение выпусков Host: другого держателя ключей R2 во флоте нет. Участник рации с адресом points, со своим хранилищем — Durable Object с SQLite.

точка строка реестра: какие блоки, когда, чья машина, почему блок 1 МиБ файла, сжатый zstd; имя — SHA-256 содержимого хозяин машина, которой сессия принадлежит сейчас; точки линии кладёт только он линия · ветка путь от последней точки хозяина назад; всё, что не на нём, — ветка временный ключ R2 ключ S3 на час, выдаёт Cloudflare

Не делаетне видит байтов разговоровне снимает и не поднимает — это модуль Host pointsпометку «в R2» не хранит — она у сессии на её машинесам машинам не пишетжурнал флота не ведёт — это ledger

Каналы points

    
С relay — по двум привязкам, как у любого Worker-участника; через них же — кадры в журнал флота. К R2 — своя привязка, только чтобы удалять: при уборке и при удалении сессии. Байты идут мимо points: машина пишет и читает R2 по S3 временным ключом. Нажмите номер.

  

  

    
    

  







  

    
Хозяин сессии, линия и ветки

    
Две машины не пишут одну сессию: точку линии реестр принимает только от хозяина. Хозяин меняется одной записью — точкой подъёма с expect: «ожидаю, что хозяин сейчас laptop». Номера точкам даёт реестр, поэтому счётчик поколений не нужен. Пройдите жизнь одной сессии.

Линию и ветки реестр не хранит отдельно: у каждой точки есть base — от какой она идёт. Линия — путь от головы назад по base, остальное — ветки. Почему ветка появилась, видно по why её первой точки и по точке, которая ушла от общей основы: подъём на другой машине — «до подъёма», на той же — «до отката», yield — «дописано вернувшейся машиной». Пульт получает готовое поле line и ничего не вычисляет.

Уборка раз в сутки

    
Будильник Durable Object. Удаляет только то, что реестр сам вывел из оборота, — пустой реестр не удалит ничего. Блок живёт, пока на него ссылается хоть одна точка.

  

  

    
    

      
    
        
  1. Правило хранения по каждой сессии — строки ушедших точек стираются.
    2. 
        
  2. Сессии без точек год — стираются целиком.
    3. 
        
  3. Блоки без ссылок — BUCKET.delete по привязке, затем строка блока.
    4. 
        
  4. Итог — в обзоре points.list: когда, сколько блоков и байт ушло.
    5. 
      

      
points.delete делает третий шаг сразу, для блоков одной сессии: строки сессии стёрты — её блоки без ссылок уходят из R2 в том же запросе. Блоки, общие с копиями и другими сессиями, остаются. Отмены и состояния «удалена до…» нет.

      
Блок, который машина положила, а точку не прислала (Host упал между ними), в реестр не попал и уборкой не удаляется — следующая точка той же машины возьмёт его как уже лежащий. Отдельного поиска сирот нет.

Сбои и остановка

    
Всё, что points знает, лежит в SQLite объекта и переживает любой перезапуск. Остановкой управляет Cloudflare: для машины это offline или disconnected на один запрос; точку повторит её следующий повод.

API Cloudflare не выдал ключ R2агент по журналу pointsточка этого повода: r2_failed, машина пишет строку в свой журнал

          
машина положила блоки и упала до points.putследующая точка этой машиныничего: блоки в R2 пригодятся

          
старый хозяин вернулся после пожарамодуль Host points на нём: not_owner → yieldничего: дописанное им — ветка

          
два подъёма одной сессии сразувторой получает not_owner и убирает свою сессиюничего

          
уборка или points.delete оборвались на серединеследующая уборка — всё сначаланичего: удаление повторяемо

Журнал points — Workers Logs, одна строка JSON в общем формате журналов: part: "points", слово и причина. События для людей — перенос, копия, откат, удаление — кадром ledger.add в журнал флота; история точек — у самого points.

Worker-модуль

relay

Транслятор рации в Cloudflare: один Worker и один объект флота. К нему по веб-сокету подключаются Host каждой машины, телефон, пульт и скрипты, а другие Worker-модули — по привязке. relay держит соединения, собирает из них общий список сессий и везёт кадры по адресу. Секретов у него нет, на диск он не пишет, что внутри кадра — не разбирает.

Host программа на машине, ведёт её сессии Claude Code callsign site@laptop — сессия site на машине laptop кадр JSON-сообщение с полем type attachment карточка соединения: кто это, его сессии roster все сессии, клиенты и участники флота участник Worker-модуль на рации, говорит по привязке привязка Service Binding: вызов другого Worker внутри Cloudflare

Не делаетне проверяет подпись ключане шлёт пушейне знает функций модулейне помнит запросовне раздаёт файлы

Каналы relay

Шесть каналов — других нет. Четыре веб-сокета снаружи и две привязки внутри Cloudflare. Нажмите номер: кто начинает, чем проверяется, что идёт и что бывает при обрыве.

API relay

Два входа. Веб-сокет — для Host и клиентов: шесть своих имён кадров, остальное relay везёт не разбирая. Привязка — для участников-Worker: один метод frame в каждую сторону и hello() при старте объекта.

    Что relay берёт у gate
    
      
    Только ответ: роль, имя и номер ключа. Секрета флота и списка отозванных у relay нет — их видит один gate. Ключи выдаёт инструмент gate switchboard invite, отзывает — запись номера в настройку gate и выпуск gate и relay.
    
      
    const r = await env.GATE.verify(hello.key)
// { role: "host", name: "laptop", kid: "k7f3" }
// { error: "revoked" }   → close 1008 revoked
// исключение             → close 1008 gate_unavailable
    
    
    
  
    

    



    
  
    
    
    Как Worker-модули говорят друг с другом
    
    
    Worker-модуль на рации — участник: у него есть имя, он получает адресованные ему кадры и шлёт свои. Кадры идут через relay, как у всех, только по привязке вместо веб-сокета. Прямой вызов функции другого модуля — исключение.
    
  
    
  
    
    
    
      Кадр через relay — всегда, когда можно
      
      
    • адрес, from, reply и offline — те же, что у веб-сокета
    • участник виден в roster со своим контрактом
    • новый участник — без правки кода relay
    
    
    
    
    
      Прямой вызов — только когда кадр невозможен
      
      
    • только к контракту вызываемого
    • в рации один такой вызов: gate.verify

      Сбои и остановка
      
    
      Поднимаются только ожидаемые ветки. Всё прочее — чистый перезапуск объекта. Остановкой Worker-модулей управляет Cloudflare: для relay это выпуск, после него каждый шлёт hello заново. Сохранять relay нечего.
      
  
      
  
      
    
      
      
      
        
      что случилосьчто делает relayчто видят остальные
      
        
          
      объект уснулничего: соединения и карточки держит Cloudflare; проснувшись, снова зовёт hello() участниковничего
      
          
      выпуск relayничего: Cloudflare перезапускает объект и рвёт соединениявсе переподключаются, hello; свои ждущие запросы — disconnected
      
          
      выпуск gate или pushничего: соединения relay целыничего; следующий вызов идёт в новую версию
      
          
      gate не ответил на verifyзакрывает этот hello: 1008, gate_unavailable; строка в журналеподключившийся повторяет с растущей паузой; уже подключённые не замечают
      
          
      участник не принял frameотправителю — offline, строка в журнале с причинойотправитель — слово; соединения целы
      
          
      участник не ответил на hello()участника нет в roster, строка в журнале; спросит при следующем старте объектаклиенты не видят его возможностей; кадры к нему — offline
      
          
      Host ушёл: обрыв, обновлениеего сессии — из roster, roster — всемновые кадры к машине — offline; ждущие ответа от неё — disconnected у отправителя
      
          
      Host вернулся, старое соединение полуоткрытоновый hello машины закрывает прежнее: 1000, replacedв roster новое since машины
      
          
      клиент ушёлroster без него — всемHost по roster снимает его зрителей; пуш телефону решает модуль push Host
      
          
      отзыв ключаничего сам: выпуск gate, затем выпуск relayвсе переподключаются; отозванный получает revoked
      
          
      кадр не по контрактуотказ словом, строка в журналеотправитель — слово

      Своего цикла перезапусков у relay нет: объект создаётся заново первым же соединением, а паузу задают подключившиеся. Host, получивший replaced, не переподключается: второй Host на машине — ошибка, её чинит агент по журналу.

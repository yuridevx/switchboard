# Прототип дизайна на настоящем фронте

Настоящее веб-приложение этого дерева, связь с продом только на чтение, мок нового из дизайна и комментарии к любому элементу страницы.

## Три команды

```
node scripts/proto/serve.mjs <папка дизайна> 4800            # сервер; пульт по умолчанию, ?app=phone на странице
node scripts/proto/invite.mjs proto-<имя> <почта> <папка дизайна>/invite.txt --port 4800   # ссылка входа — в файл
node scripts/proto/watch.mjs <папка дизайна> 30              # ждёт комментарий, печатает и выходит
```

Ссылку из `invite.txt` открыть в браузере один раз: пропуск останется в браузере. Комментарии: кнопка «Комментировать» внизу слева или Alt+C, клик по элементу.

Любое веб-приложение репо: `--app <имя>` или `?app=<имя>`; нужен `web/<имя>/stand/parts.ts` с `export function <имя>Parts()`, адреса прода — `https://<имя>.pfarm.app/build.json`.

## Папка дизайна

- `mock.ts` — `export default { … } satisfies ProtoMock<State>` (`@proto/api`):
  - `owns` — запросы договора дизайна: их отвечает только мок, в прод они не уходят никогда;
  - `state()` — состояние мока в памяти страницы;
  - `answer(f, ctx)` — ответ по кадру и `ctx.state`. Взаимодействия с новым («добавить», «сменить», «удалить», «подключить», «убрать») меняют `ctx.state`, следующие ответы показывают результат. `ctx.real(f)` — настоящий ответ прода, чтобы дополнить его;
  - `harmless` — записи, которые страница шлёт, но они ничего не меняют во флоте;
  - `roster(r, state)` — правка roster одной машины;
  - `workers` — службы, которых в проде ещё нет: имя → адрес-заглушка; кадры к ним тоже только мок;
  - `init(ctx)` — загрузить данные до старта.

Мок обязателен для всего нового: мок-данные и мок-взаимодействия. Если мок молчит на запрос из `owns` или на кадр к службе-заглушке, это ошибка прототипа: страница сразу показывает тост «ошибка прототипа · мок молчит на …», в консоли — тот же текст, запрос получает отказ `no_mock`, а не `offline` прода.
- `data.mjs` — необязательно: `export function <имя>(params)` — данные с диска машины, в моке — `ctx.data("<имя>", params)`.
- `comments.json` — пишет сервер.

## Что уходит в прод

Ядро отдаёт каждый запрос модуля шву `StartOptions.seam`:

- чтения и безвредные записи — в прод;
- ответы мока — вместо прода;
- `prefs.set` хранится в памяти страницы;
- остальные записи не отправляются: на странице тост «прототип: не отправлено» с телом запроса.

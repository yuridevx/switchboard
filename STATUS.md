# Switchboard — карта и состояние

Система с нуля по дизайну `docs/designs/from-scratch/index.html`. Старая система — тег `v1`.

## Части

| папка | что | чем проверяется |
|---|---|---|
| `protocol/` | `@sb/protocol`: конверт кадра, адреса, пропуск `флот:номер:секрет`, договор-код (`request`, `frame`, схемы zod), журнал одной формы, общий клиент (`createApi`, `httpTransport`, `socketLink`) | `cd protocol && npx vitest run` |
| `platform/` | Worker `sb2-platform`: объект флота (люди, пропуска, проекты, картина, сокеты страниц) и объект машины (сокеты Host, Keeper, зрителей; доставка кадров). Вход привязки для служб — `platform/src/contract.ts` | vitest в пуле Workers |
| `services/` | Worker `sb2-services` без состояния: вход `POST /call`, сервер MCP `/mcp`, файлы страницы, проход сокетов `/f/*` и `/m/*` в платформу; модули `src/modules/<имя>/`; записи модуля — объект `Records` на модуль и флот (архив — на машину); файлы — R2 | vitest в пуле Workers |
| `host/` | Node + Claude Agent SDK: ядро (сессии, документ, связь, хранилище) и модули chat, accounts, profiles, points, proxy, shell, incidents, machine | vitest со стендом (поддельные SDK, связь, держатели) |
| `keeper/` | Go: служба ОС, держит Host и себя, держатели процессов | `go test` |
| `web/` | React 19 + Mantine 9 + Vite: одна страница, две раскладки; мок флота для прототипа | vitest + снимки `npm run shots` |
| `tools/` | гейт импортов, выкладка, проверка флота | — |

## Правила для исполнителей

- Один адрес флота: всё идёт в службы (`/call`, `/mcp`, `/f/<флот>`, `/m/<флот>/<машина>`, страница); службы зовут платформу привязкой.
- Запрос описан один раз в `protocol/src/contracts/`. Новое имя — туда, с хозяином; обработчик берёт уже проверенный ввод. Договор правится только добавлением; перед правкой перечитать файл: его правят и другие.
- Модуль импортирует чужое только через `@sb/protocol` и вход пакета. Циклов нет: службы → платформа → протокол.
- Каждый запрос несёт `trace`; каждая часть на обратном пути дописывает в `reply.spans` свой отрезок `{part, ms}`; на каждый запрос — одна строка журнала (`logger` из протокола) с `type`, `from`, `to`, `ms`, `ok`, `word`, `trace`.
- Ошибка обработчика — отказ `module_failed` и строка журнала; модуль не выключается. Отказ — `throw new Refusal(слово, причина)`.
- У каждой операции предел (`within`, `CALL_MS`) и штатная остановка.
- Просто: только ожидаемые ветки; без повторов, запасных режимов и обратной совместимости.
- Язык: идентификаторы по-английски, комментарии и тексты интерфейса по-русски.
- Тесты: эталон закрепляет одно свойство на зафиксированном входе. На этой машине: запускать из пути с большой `D:/`; `setTimeout(0)` спит около 10 мс.
- Зависимости уже поставлены в корне репо. Новая зависимость — в `package.json` своей папки и `npm install` из корня (если упал — повторить: рядом могут ставить другие). `npm install-scripts approve <пакет>` — если нужен установочный скрипт.
- Свои файлы — только в своей папке. Не коммитить: коммиты делает главная сессия.
- Ресурсы Cloudflare v2 — с приставкой `sb2-`; ничего не выкладывать: выкладывает главная сессия. Секреты — из `~/.switchboard-dev/v2-cloudflare.env`, не в репо и не в argv.

Приём докачивается: файл, не уложившийся в предел запроса (2 мин), остаётся черновиком `uploads/.<хэш>.part`, повтор сообщения продолжает с места. Блоков-картинок в ввод не кладёт никто (отказ `bad_attachment` ушёл); обращения служб компьютера кладут файл сразу в хранилище. Страница: любой файл из поля ввода, файл и сайт в ленте на месте вызова инструмента, скачивание, один лист «целиком», схема из блока `mermaid`, одно правило вида показа (`showKind`). Аккаунты и модели (15 нояб. 2026, дизайн `docs/designs/v2-accounts`, https://claude.ai/artifact/HCfNrYCPYLyw5LW3VC7Jps; ветка выпуска `release/v2-accounts`): очередей аккаунтов, входов Claude на машинах и Remote Control нет — аккаунт Claude это ключ флота с протоколом `claude` (имя — почта, значение — годовой токен `claude setup-token`), он заводится один раз на флот запросом `keys.set`; у процесса сессии вместо токена слово-заглушка, настоящий токен ставит прокси машины. Аккаунт сессии выбирает машина (`host/src/modules/accounts/limits.ts: choose`): годен → остаток → счёт = остаток ÷ часы до сброса ÷ (1 + тёплые сессии) → лучший; сессия держится аккаунта, пока кэш её разговора тёплый, отказ лимита Claude уводит тот же вызов на следующий аккаунт и сессии не достаётся, числа лимитов — из заголовков ответов Claude. Документ сессии называет провайдера и точную модель — `key` (`claude` или имя ключа флота) и `model` из каталога `keys.models`: без них отказ `key_required` / `model_required`, модели нет в каталоге — `no_model`, «/model слова» сообщением меняет модель (`many_models`, `no_model`); у ключа флота поле `protocol`, полей `model`, `models`, `window` нет. Решения и события аккаунта — строки журнала машины (`route`, `account.moved`, `account.full`, `account.closed`, `account.token`, `call`), журнал уходит в ClickHouse (`log.write`) и читается `log.query`; в строке сессии — `cache {until, compact}` и `answers`, ядро само сжимает разговор от 200 К на 54-й минуте простоя (`host/src/core/session.ts`). Экран «Флот → Аккаунты» — столбцы аккаунтов, флаг «беречь запас Fable», лента переходов; в разговоре аккаунта и лимитов нет; эталоны — `host/test/accounts.test.ts`, `host/test/cache.test.ts`.
